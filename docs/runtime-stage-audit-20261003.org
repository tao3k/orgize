#+TITLE: Native Org runtime stage audit and measurement repair

* Changes and authority

=runtime-profile= is an explicit diagnostic feature, independent of the two
execution-owner features. Ordinary builds compile the stage wrapper to the
original operation without clocks or a thread-local collector. Profiling uses
a synchronous request-local collector; nested measurements fail closed and
panic cleanup resets the collector. Native roots never cross thread boundaries.
The module shell contains only file-backed declarations and re-exports.

The original public =Org::try_parse= path is unchanged in authority. Stage
wrappers observe request encoding, native transport, event decoding, Rowan
construction, graph projection/index/ancestor calculation. They do not provide
another parser or a fallback. Native transport is explicitly inclusive of owner
admission, Scheme execution, tape serialization and result transfer. It is NOT
isolated Scheme parser CPU time or GC attribution.

* Benchmark correctness repair

=orgize.runtime-parallel.v2= distinguishes =qualification= (lossless round-trip
plus complete tree/graph checksum) and =performance= (those checks disabled,
artifact=null). Performance mode still executes the same public parse/projection
and document destruction; it does not silently omit production graph work.
Profiling and mode are part of comparator identity. A performance receipt is
never semantic validation evidence. Qualification hashes must match the previous
same-program/corpus receipts independently of diagnostic adapter changes.

Supervisor queue and IPC-service durations are measured on each individual
request. They partition that request's submission-to-response time; per-stage
percentiles are reported independently and must not be subtracted. Native
transport and supervisor IPC stages are inclusive; they must not be summed with
their child phases. Validation/checksum and document destruction are timed
separately. Stage diagnostic JSON formatting is not labelled as validation.
Whole-batch throughput remains end-to-end, not bare Scheme parse throughput.

The fixed-scale stage qualification is 1,000 and 10,000 distinct documents,
64 Tokio callers and 8 independent exec'd native domains per feature. This is
not a new production process-pool API or proof of per-domain actor parallelism.
The previous three-domain-count matrix remains historical evidence for that
different benchmark version. Only completed current receipts qualify this slice.

* Verification status

The first diagnostic layout triggered RUST-MOD-R008 (inline module). Splitting
the implementation then triggered RUST-MOD-R001 (implementation in mod.rs).
Both were repaired by separating collector/dispatch from the module shell;
the current-source policy check passed without changing warning severity.
Fresh matching binaries, unit/consumer and scale results are recorded only
after their execution. Earlier intermediate binaries are not final receipts.

Both =runtime-rust= and =runtime-scheme= without =runtime-profile= passed
offline =cargo check --tests --benches --examples= via the maintained owner
Justfile recipe (40.53 s and 35.54 s respectively). These are compile checks,
not additional full runtime test passes. Dev opt-level 2, debug/assertion/overflow
settings and release opt-level 3 were not reduced for this slice. No kernel
patch, alternate parser or production process pool was introduced.

* Remaining optimization gates

1. Split native owner wait, Scheme fold, tape serialization and root/copy costs
   with native monotonic timings; capture CPU, allocation and GC separately.
2. Lower admitted fixed event-fold rules to direct native Scheme functions;
   static declaration/type/state admission must not remain repeated hot work.
   Keep POO strategy ownership and ordinary functional code, not a Rust parser.
3. Use measured allocation/scanning costs to fuse intermediate event/tape
   projections and prepare immutable graph rules once; retain document checks.
4. Add diverse real-size/complexity corpora, repeated interleaved samples,
   concurrency sweeps and open-loop overload/SLO qualification for both owners.

This receipt does not claim these remaining optimization gates are complete.
