do not prevent later documents from parsing.

contains a pure bounded loop, not a new scheduler or parser. Rust still owns
its request queue under =runtime-rust=; the existing native Scheme actor still
owns the lifecycle and calls under =runtime-scheme=. No nested actors, foreign
thread attachment, VM SMP, or Gambit kernel patch were introduced.

the same Rust Rowan/Element projector used by single-document indexing.
Document path/order, duplicate source entries and configuration remain
per-document. Empty indexing performs no native work. Oversized sources
use the existing native single-document entry; they do not enter a legacy
parser. Large-project indexing keeps its original outer concurrency and
partitions each worker's inputs into the same bounded native packets.

* Whole-batch diagnostic integration

Operation 7 now emits =OBP1=, six little-endian u64 fields, and the unchanged
=OBT1= payload with OPR1 document rows. Operation 6 and ordinary scalar
parsing do not sample these counters. The fields are:

| Offset | Field | Unit | Scope |
|--------+-------+------+-------|
| 4 | batch_body_wall_sum | ns | Batch framing, parsing, OBT1 assembly |
| 12 | batch_owner_thread_cpu_sum | ns | Same owner OS thread |
| 20 | batch_process_cpu_interval_sum | ns | All OS threads of this process |
| 28 | batch_vm_gc_cpu_interval_sum | ns | VM-wide GC CPU interval |
| 36 | batch_vm_gc_wall_interval_sum | ns | VM-wide GC wall interval |
| 44 | batch_vm_gc_count_interval_sum | count | VM-wide collection interval |
| 52 | OBT1 payload | bytes | Existing ordered document records |

Rust collector names use the =native.= prefix. VM/process interval sums must
not be interpreted as exclusive costs if intervals overlap. Process CPU and
GC snapshots enclose a slightly wider interval than wall/thread clocks;
snapshot allocation can trigger a collection. Initial ONR1 header admission,
the outer OBP1 copy, FFI entry/return, owner scheduling and Rust projection
are outside the batch body wall interval. This is not an entire Query timer.

Rust rejects wrong OBP1/OBT1 identities, truncation, wrong counts, trailing
bytes and ordinary/diagnostic mode mismatches without compatibility fallback.
Whole-batch counters are committed only after complete batch wire admission.
The existing per-document diagnostic stages retain their own behavior.
Without =runtime-profile=, requesting diagnostic batch decode is rejected.
The parallel scale log label is now =observations= rather than =stages_ns=,
because that map includes both durations and counts. The older 48-document
diagnostic scenario still has a =stages_ns= label; any count fields in that
map must not be interpreted as nanoseconds. Its label cleanup remains pending.
