The existing request-local collector records raw stage totals for each

Scheme sampler, JSON request transport, or second parser.

Stage boundaries:

- =query.total_inclusive=: complete query work, including walking and reads.
- =native.owner_admission=: admission and wait before native processing.
- =native.owner_service_inclusive=: owner processing including copy.
- =native.result_copy=: existing transport result-copy timing.
- =native.completion_handoff=: completion-to-caller timing.
- =native.scheme_fold= / =native.tape_encode=: inner Scheme wall durations.
- =native.scheme_thread_cpu=: CPU of fold plus tape, not fold-only CPU.
- Rowan and graph timings: existing Rust-owned projections.

Inclusive stages overlap and must not be added together. Diagnostic clock
overhead means profiled results do not replace unprofiled performance
qualification or prove a speedup.

** Outcome and next boundary

No production algorithm or runtime architecture was changed this turn.
The executable diagnostic closes the observability gap, not the
performance gate. Earlier wall-only evidence does not support a fixed
claim that Scheme is intrinsically four times slower, nor does this small
sequence establish the reverse ranking.

Next investigate bounded native request batching / owner handoff against
the existing functional Scheme =org-parse-batch= surface, preserving
per-document order, errors and source identity. This is an optimization
hypothesis, not an implemented capability or a kernel patch.
Any implementation must requalify both owners without diagnostic clocks,
retain 1,000/10,000-document high-concurrency testing, and keep the same
strict gate. Do not replace large-corpus concurrency with one VM call or
change zero warmups to turn this gate green.
