* Shared Python host-child gate and initialization policy boundary
The new bindings/python/tests/test_host_children.py runs an isolated Python

Justfile python-test-installed now accepts an optional pytest name filter; both
checks used that maintained entrypoint. No runtime or Gambit kernel edit was
made. Scoped git diff --check passed.

Pinned dcd677c setup.c initializes OS/memory before invoking the program linker.
Its setup_params reset fields provide heap/error hooks but no child-reaping
ownership policy. os_setup.c unconditionally enters I/O module setup, which
installs the process-wide SIGCHLD handler. Thus a program linker callback cannot
prevent the earlier handler-installation window. Blocking SIGCHLD solely on
the runtime owner thread would not fence other already-running host threads.
Restoring a handler only after setup is not initialization-race qualification.

A startup-only embedding contract would require explicit host-wide admission:
no existing or newly spawned children during setup, no concurrent initialization
from arbitrary host threads, and a defined policy for Scheme-owned children and
cleanup-time signal restoration. This changes the current lazy public API
contract and has not been authorized or implemented. Keeping unrestricted lazy
initialization instead requires a supported runtime host-child ownership seam;
none was found in the inspected pinned setup API. Do not silently introduce
kernel patches, symbol interposition, process fallbacks or serialized tests to
declare this gate green. Obtain direction before changing the host contract.

The deterministic corpus alternates doc.org, plain-links.org and quote-heavy.org,
adding a unique numbered title, heading and link to each. All strings are checked

scaling; broader real-world document sizes and structures remain separate work.

hashes both its complete Rowan tree and Element graph; an ordered aggregate hash
is independent of completion order. Caller counts/repetitions must agree within
each runtime. runtime-corpus-compare rejects wrong backends, duplicate
batch identities, incomplete/distinct count differences and mismatched corpus,
artifact, program, benchmark source, architecture, byte count or queue settings.
