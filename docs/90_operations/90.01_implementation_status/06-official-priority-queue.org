*** M25 Official Org Alignment Priority Queue

This is the refreshed backlog table for "which major Org-mode capabilities
should orgize align next".  It differs from the M24 audit above: M24 records
the broad official capability map and historical coverage, while M25 is the
ordered implementation queue. Its source references are pinned upstream Org
manual/runtime revisions and research-only AST/exporter comparisons. Those
implementations do not enter Cargo, CI, tests, generated artifacts, or release
packages.

Priority rules:

- P0: everyday agenda/search/planning behavior that downstream agents and UIs
      need to trust.
- P1: high-value Org workflows that should become semantic side tables or
      non-executing plans before exporter/frontend work depends on them.
- P2: useful parity work that should remain opt-in, filesystem-aware, or
      explicitly out of the parser core.
- Out-of-core: interactive editing, code execution, network handlers, live
      Emacs state, and source mutation.  orgize can expose safe plans or lint
      evidence for these, but should not perform the action.

Recommended implementation order for the next major PR train:

1. M25.1 workspace agenda command plans, because it unlocks realistic Org
   agenda/blog/agent consumers over more than one file.
2. M25.2 agenda urgency and receipt fidelity, because it makes the multi-file
   agenda explainable and rank-stable.
3. M25.3 citation export planning, because orgize already parses citations but
   lacks the bibliography side table needed by serious writing/export flows.
4. M25.4 Agent capture protocol and wasm plan DTO, because org-zhixing and
   Window/Agent consumers need a native Org entry preview rather than an Emacs
   template parser.
5. M25.5 publishing/site graph and M25.6 attachment inventory, as opt-in
   workflow projections after the agenda/export/capture substrates are stable.
6. M25.7 export dependency graph, so downstream blog/frontend consumers can
   explain cross-file include/setupfile/bibliography/macro/output relationships
   without executing export.
7. M25.8 table visualization metadata, so Org Plot and radio-table consumers
   get table-shape and option plans without gnuplot, translator, or source
   mutation in core.
8. M25.9 Org Crypt projection, so index/export/frontend consumers can see the
   sensitive-body boundary without decrypting or executing Org Crypt.
9. M25.10 runtime metadata projection, so feed/timer/mobile/persist evidence
   is available as a safe side table without network, filesystem sync, or cache
   execution.
