*** M24 Official Org Priority Audit

This historical audit used the pinned official Org manual and front-line
modules as reference evidence. The upstream implementation is not an input to
Cargo, CI, tests, generated artifacts, or released packages.

Priority is assigned by common Org usage and by how early/prominent the feature
appears in the official manual and runtime modules:

- P0 means it affects everyday agenda, search, planning, lint, or agent use.
- P1 means it is a popular Org workflow and should be modeled as semantic
      metadata/projection before exporters rely on it.
- P2 means it is important for parity, but should stay opt-in or side-table
      based until the core parser/projection surface is stable.

**** Official Org Capability Alignment Table

This table is the working queue for "what powerful Org-mode capabilities should
orgize introduce next".  It deliberately favors parser-owned syntax, semantic
projection, lint, and non-executing plans.  Interactive editing, filesystem
mutation, code execution, network protocols, and global ranking remain outside
orgize core unless represented as source-grounded metadata.

**** P0 Agenda Match And Filtering Semantics

Official anchors: `doc/org-manual.org` sections "Agenda Views",
"Matching tags and properties", "Properties and Columns"; `lisp/org-agenda.el`
match/filter code.

- [X] Add an official-style match expression parser alongside the existing
      required/excluded tag filters for `+tag`, `-tag`, top-level tag OR groups,
      TODO state predicates, property predicates, and comparisons.
- [X] Add `AgendaMatchQuery` or equivalent typed API instead of overloading raw
      strings across consumers.
- [X] Support inherited tags, file tags, document/category properties, TODO
      keyword state, priority, and planning timestamp predicates in one query
      evaluator.
- [X] Add snapshot and field-level tests for match expressions that combine
      tags and properties, including negative matches and missing properties.
- [X] Expose match-query examples in wasm so agenda/indexer consumers can
      inspect the active query and matched rows.

**** P0 Workspace Index And Cross-File Resolution

Official anchors: `doc/org-manual.org` sections "Handling Links",
"Attachments", "Properties and Columns"; `lisp/org-id.el`, `lisp/org-attach.el`.

- [X] Add a workspace-level semantic index builder over document-local section

- [X] Aggregate cross-document targets, links, attachment directories/links,

- [X] Emit deterministic diagnostics for duplicate `ID`/`CUSTOM_ID` targets and

**** P0 Priority, Effort, And Property Drawers

Official anchors: `doc/org-manual.org` sections "Priorities", "Properties and
Columns", "Clocking Work Time"; `lisp/org.el`, `lisp/org-colview.el`,
`lisp/org-duration.el`.

- [X] Replace `Section::priority: Option<String>` with a typed priority domain
      carrying the normalized priority cookie and source value.
- [X] Parse default priority semantics (`A`, `B`, `C`) into projection metadata
      while keeping raw priority text for compatibility.
- [X] Align priority cookie grammar with official
      `org-priority-value-regexp`: uppercase `A-Z` or numeric `0..64`,
      including two-digit numeric cookies such as `[#64]`.
- [X] Parse common duration values from `EFFORT`, clock summaries, and
      property drawer values into typed duration metadata.
- [X] Add a property side-table/index for fast lookup by inherited and local

- [X] Add lint rules for malformed priority cookies, malformed duration values,

- [X] Add an explicit priority profile for Agent consumers that carries

      widened alphabetic priority ranges.
- [X] Project the `org-get-priority` urgency score / sortable key next to the
      normalized value for agenda and Wendao index consumers.
- [X] Add profile-aware lint configuration once callers can pass non-default

**** P0 Source Block Results And Tangle Metadata

Official anchors: `doc/org-manual.org` section "Working with Source Code";
`lisp/ob-core.el`, `lisp/ob-tangle.el`, `lisp/org-src.el`.

- [X] Model `#+RESULTS:` blocks/keywords as first-class semantic records linked
      to the preceding source or inline source block.
- [X] Parse and normalize common Babel header args beyond the current raw
      `:key value` projection: `:results`, `:exports`, `:eval`, `:session`,
      `:var`, `:noweb`, `:tangle`, `:dir`, and `:cache`.
- [X] Add a source-block side table for language, name, result, header args,
      coderefs, and tangle target metadata.
- [X] Add a source-block reference side table for literate programming:
      =#+CALL:=, inline =call_name(...)=, and noweb =<<name>>= references are
      resolved against local =#+NAME= and =:noweb-ref= declarations without
      executing Babel.
- [X] Add a safe, non-executing source tangle plan that groups blocks by
      explicit or caller-provided targets and records disabled/inline/missing
      target skips without writing files.
- [X] Add lint rules for missing block names referenced by noweb, =#+CALL:=, or
      inline calls, unsafe/eval-sensitive headers, duplicate =#+NAME:=, and
      invalid tangle targets.
- [X] Keep execution out of orgize; only parse, index, lint, format, and
      project metadata.

**** P2 Export, Publishing, And Include Semantics

Official anchors: `doc/org-manual.org` sections "Exporting", "Publishing",
"Include Files"; `lisp/ox.el`, `lisp/ox-*.el`, `lisp/org-macro.el`.

- [X] Expand the typed `#+OPTIONS:` model beyond `H`, `-`, and `e` to cover the
      high-usage export toggles for TODOs, tags, timestamps, author/date/title,
      drawers, planning, priorities, broken links, and section numbering via
      the opt-in publishing side table; `ExportSettings` remains the minimal
      compatibility surface used by current exporters.
- [X] Model `#+BIND:`, `#+SETUPFILE:`, `#+EXPORT_FILE_NAME:`, and backend
      `#+ATTR_*` settings as side-table metadata without executing Emacs Lisp.
- [X] Model `#+TAGS:` vocabulary shortcuts and explicit `#+PYTHON:` directives;
      expose a recursive org-elements JSON payload and opt-in host execution
      API so Python, TypeScript, CLIs, and other tools can bind to semantic Org
      sections, elements, objects, targets, footnotes, and source blocks without
      running code during parse.
- [X] Add a flat org-elements node index with stable ordinal/category/kind,
      source range, outline path, context, and summary fields so downstream
      tools can perform `org-element-map`-style filtering without recursively
      walking the full payload themselves.
- [X] Promote the flat node index from JSON-only output to a typed Rust API
      (`Document::org_elements_index`) plus an index-only wasm projection
      (`orgElementsIndexJson`) for lower-cost TypeScript/Python consumers.
- [X] Add a typed `OrgElementsIndexQuery` and filtered JSON/wasm projection so
      consumers can select category/kind/context/outline subsets without
      loading or walking the whole org-elements tree.
- [X] Add an explicit include expansion plan for `#+INCLUDE:` line/range/options
      semantics; keep expansion opt-in and filesystem-aware only in lint/export
      helper APIs.
- [X] Keep publishing out of core parser execution, but parse publishing-related
      links/options well enough for lint and export projection.
