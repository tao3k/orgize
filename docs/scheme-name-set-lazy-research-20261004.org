* Change and invariant
The preceding candidate allocated its name-table hash at the start of every
=run-event-fold=. The new candidate binds a private pending marker and creates
the hash only on the first =fold-name-index= call. Later calls reuse the same
request-local, identity-keyed, 128-table-bounded cache. Outside a request, the
default remains no retained index. All name-table admission, membership and
source-bound checks remain live in their original semantic positions.

Tests prove that an unrelated predicate leaves the pending marker untouched,
that the first name query creates exactly one retained table entry, subsequent
queries reuse it, malformed tables are not retained, and the outer parameter
binding is restored. Existing cross-request mutable-IR and cross-source tests
remain green. No global source/IR cache, kernel change, concurrency reduction,
Cargo optimization change, or new public authoring DSL was added.

* Next broader seam and open gates
=call-source-helper= calls =fold-initial-states= for each invocation;
=fold-initial-states= validates and maps every declaration to a fresh state
entry. State lookups use =assq= and persistent updates scan the state list. Those
are concrete implementation seams, not a proven dominant CPU attribution.
Sharing admitted immutable helper defaults is worth a separate A/B experiment,
provided functional updates, helper arguments, duplicate-name behavior and
request isolation remain unchanged. It must not mutate shared state cells.

Exact dynamic predicate/state-update frequency remains unmeasured. Broad
fixed-corpus results, the strict Query gate, native Rust/Scheme feature closure,
Python qualification and 1000/10000-document repeated high-concurrency matrices
remain open. Earlier failed timings and incomplete matrices are not replaced by
these small-fixture passes.
