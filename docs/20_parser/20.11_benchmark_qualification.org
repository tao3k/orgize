#+title: 20.11 Orgize Benchmark Qualification

* Package boundary

=build.ss= owns the production package. It does not load or build any target
from =t/benchmarks=, and the production =gerbil.pkg= does not declare ASP.
Git checkouts may contain benchmark source files; package installation does
not compile or install benchmark modules, tooling dependencies or receipts.
An empty downstream directory loaded the installed Org Fold and parsed a
document using the production prefix. Both benchmark imports failed module
resolution in that process. Benchmark scenarios run from the development
checkout with explicit development dependencies.

Development prepares the existing =dev/gerbil.pkg= in a separate
=GERBIL_PATH=, with the prepared production library on =GERBIL_LOADPATH=.
Scheme benchmarks have no separate build script, compiled output prefix or
cleanup recipe. Rust continues to use Cargo's existing Criterion targets.
The Orgize library disables Cargo's implicit library benchmark harness.
The standard unit-test invocation still runs the library tests and gives
the native startup fixture its own exclusive process. The benchmark command
runs the explicit Criterion targets without starting a second parallel
copy of the library test suite.

[[file:../../test-benchmarks.ss][The benchmark test entry]] discovers the
scenario suites with =std/test=. It checks source semantics and the helper
counter contract. Run it from the checkout with the production dependencies
and ASP development prefix available. Gerbil loads the scenario source
directly. Measured runs still use the scenario fixtures and their original
ASP admission gates.

Prepare the development prefix separately. Run each source benchmark in
its own process with the production library before the development library.
Both dependency trees contain POO modules, so this order keeps the production
Parser and POO artifacts together while resolving the benchmark API from
the development prefix.

#+begin_src sh
orgize_production="$PWD/.gerbil-ci"

GERBIL_PATH="$orgize_development" GERBIL_LOADPATH="$orgize_production/lib" \

  gxi t/benchmarks/org-prefix-probe.ss local \
  t/benchmarks/org-prefix-probe/benchmark.ss /tmp/orgize-prefix-local.receipt
#+end_src

thread. Catching the join failure in the calling test did not prevent a
delayed orphan exception report during process shutdown. The authorized
bridge update to =0d92f7b= makes the coordinator return a tagged outcome

The Cargo and fuzz lockfile changes are confined to the same five bridge
packages' Git source identities. Other dependency selections are unchanged.

an error marker, followed by the intentional failure fixture's status 42.
The 600-second build, 120-second test and five-second output deadlines remain
unchanged. This correctness result does not qualify either Rust runtime's
ledger latency or replace exact-head CI.

An experiment names one cost and one candidate. Keep fixture, runtime feature,
compiler, host parallelism, iteration count and resource budgets matched.
Start with repeated runs of the same binary to establish variation. Compare
independent processes in A/B and B/A order and retain every sample, failure
and binary identity outside version control. Report P50 and P95 where the
sample count supports them; keep the ledger gate's best-of-five decision
separate. Do not add overlapping queue, service or GC intervals as though
they were disjoint costs.

Use diagnostic builds to split source read, request encoding, owner wait,
Fold and tape emission, Rust decoding and projection. Qualify gains on the
unprofiled public workload with exact event and result checks. The fixed VM
owner retains Scheme values; moving Rust projection onto that owner changes
the contention model and requires independent evidence.

Profiling receipts use =fold= for Scheme traversal, =event_tape= for the
wire representation, =owner= for queue admission and owner service, and
=ffi= for calls and copies across the language boundary.

For the ledger query, enable =runtime-profile= and set
=ORGIZE_PROFILE_PLAN_LEDGER= and =ORGIZE_PROFILE_PLAN_LEDGER_STAGES= to 1.
Run the same prepared release target under each owner. The
=fold.batch.requests= and =owner.metadata.requests= counters distinguish
the two physical request families. Their owner CPU fields measure work on
the owner thread. The overall =ffi.requests_completed= counter also
includes other operations.

* Scheme actor execution

Gerbil Parser supplies the parser primitives and the Fold machinery. Orgize
Scheme owns Org grammar, event production, document metadata, Contract
evaluation and the scheduling of actors inside each VM. Rust owns caller
admission, file I/O, capacity and lifecycle across VM owners, and delivery of
owned results. A Scheme value stays with its VM owner.

The [[file:../../bindings/c/orgize-actor.ss][existing Scheme batch]] creates
green-thread workers with private mailboxes, joins them and returns results in
input order. The standard suite covers order, parser configuration, failure
containment and caller mailbox isolation. This functional batch returns event
lists. The public tape path uses a separate bounded loop and emits tapes
directly. The Scheme runtime lane has a serving green thread, but its idle
C wait blocks the owner thread. The Rust runtime lane hands the batch to a
fixed owner through a Rust channel. Neither tape path uses the Scheme actor
batch to schedule individual documents.

The focused package test completed all six actor cases with the existing
output watchdog. The first full invocation hit the five-second output
watchdog during module evaluation. A serial replay of =just ci-scheme-test=
on the same prepared prefix passed 236 cases in 19 suites, including the
actor cases, and the existing intentional failure returned 42. Keep the
initial timeout as evidence of startup variability.

The direct-tape witness uses the bridge's =make-gerbil-rs-actor-batch=
with four persistent workers inside one VM. It compares the full ordered
tapes with direct calls, including repeated documents, Unicode, CRLF and a
repository fixture. A failed turn drains, a subsequent turn returns the
same tapes, the caller keeps its own mailbox message, and a closed batch
rejects another turn. The focused witness passed through the package test
entry point. The next full run reached 162 cases and ten suites before the
unchanged 120-second deadline. It had yet to reach the tape suite.
The maintained tape suite initially hit the five-second output watchdog
while evaluating its relative source imports. Using the installed module
identities for the tape and event-list owners let all fourteen focused cases
pass through the same entry and watchdog. The following full run completed
237 cases in 19 suites and the intentional failure control in 65.69 seconds.
The witness exercises Scheme execution and retirement inside one VM. Host
admission and Rust result delivery remain separate obligations.

The first transport experiment should run the existing direct-tape operation
as a handler of the bridge's =make-gerbil-rs-service-endpoint=, with
=SchemeServiceRequest= carrying owned input into fixed-owner Rust admission.
The current bridge pin provides those interfaces. Its Rust instance module
is Darwin-only and loads a separate VM image. Start the one-VM comparison
there with the same bounded input and byte-identical results. Linux and
the existing statically linked deployment need independent loader and
lifecycle evidence before replacing the shipping owner paths.
Keep Org source, intermediate event state and metadata inside the Scheme
turn. Move only owned request and result data across the host boundary.
Keep stateful operations bound to their owner and compare independent
documents in the same input order. A cancelled queued job is removable.
For claimed work, the owner retains capacity and roots until retirement.
Verify both paths with a full mailbox, an invalid document, cancellation
before and after claim, and close while work is outstanding.

Measure handler CPU, allocation and GC separately from admission, mailbox
wait and result delivery. Pair the current owner loop against the bridge
service using the same direct-tape handler, fixtures and concurrency. Then
test whether producing the ledger's metadata in that same Scheme turn
removes the second owner request. Today Rust creates the metadata packet
from validated graph records. A fused result must obtain keyword and title
fields from the same Fold traversal and bind each result to its
source-relative span and source identity. Rust can then join those fields
to the validated graph records without depending on a second set of
node IDs. Preserve the full graph and document metadata checks while
testing this separate algorithm change. The bridge's
[[https://github.com/tao3k/gerbil-scheme-rust/blob/9aa4de6adc1f566f78586b046ba9452c1e996d7b/docs/10-19-design/10.50-mailbox-frozen-control-4513.org][single-VM mailbox observation]]
completed 999,944.88 typed messages per second in one arm and exceeded its
backlog limit. It provides a concrete service shape to test with the Org
workload and retains its failed acceptance result.

The Ubuntu relocation run for =3358e3a5= passed the Scheme runtime's

compiler-owned archive because its Gambit link name differed from the

The archive order and content digests still bind the original link
receipt. Verify the change through the existing relocated consumption
step on the current commit.

before changing the consumer pin. The current candidate retains Parser
=3c58e6ec=. The post-squash run passed Rust Contracts and AOT performance.
The Linux and Darwin Scheme semantics jobs failed when the historical
migration fixture was absent from the squash history.

commit. Fetching the reviewed PR history made the original fixture available.

runtimes, relocated FFI, wheel and performance checks in the existing PR.

and wheel job waits for the artifact from its own platform.
