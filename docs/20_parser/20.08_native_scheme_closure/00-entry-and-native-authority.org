* Authority and evidence boundary

=479b2763fa1924385a2df824d029e9ba35341bcd=, with inherited dirty migration
preserved. Org-owned POO grammar/strategy is compiled into the native Gerbil

every downstream syntax classifier already executes in native Scheme.
Generated kind/field tables and

This ledger replaces no historical receipts and approves no snapshots.
Each syntax family needs recognition, context/configuration, exact source

* Public entry and residual execution audit (2026-10-04)

The live public chain is =src/org.rs= (alias and configured facade) ->
=OrgAotDocument::try_parse= -> =parse_org_aot_with_config= ->
=native_events::parse_events= -> native =orgize_parse_events= export.
The subsequent =parse_generated_events= call admits the supplied event tape
into Rowan; it does not invoke a source recognizer. Both runtime features
select lifecycle/queue ownership for this same Gerbil parser, not alternate
grammars. There is no =src/syntax/= legacy parser directory in this checkout.

Three categories must not be conflated:

| Category | Live source evidence | Required treatment |

This is a bounded positive inventory, not a complete enumeration of all
semantic consumers. Deleting these projections before native replacements
would break consumers; keeping them while declaring native closure would be
equally incorrect. Timestamp numeric range conversion and overflow failure
are separate from lexical sign/digit/unit admission.

=parse_org_aot_with_config= path; its plain-text recovery is not a legacy Rust
recognizer. Query/Contract =core_parser.rs= delegates expression values to
native exports. These findings do not qualify full recursive context recovery
or all Query/Contract consumers.

** Second slice: native timestamp cookie admission

Previously the Scheme recognizer accepted any sequence from
=+-.hdwmy0123456789= as a repeater/delay candidate. Rust's typed projection
then rejected malformed cookies. The new private pure declaration checks
the complete prefix, nonempty decimal magnitude, and exactly one declared
unit in Scheme before emitting =TimestampRepeater= or =TimestampDelay=.
Malformed cookies remain lossless =TimestampTrivia= inside the same timestamp.
No new kind, wire ABI, public DSL or kernel primitive is introduced.

The fresh native Scheme regression checks seven valid forms across all five
units and both warning kinds, plus ten malformed forms, exact valid token
byte offsets and LF/CRLF source partition. Rust enum/numeric decoding remains;
time/date components and complete native semantic execution remain open.
The candidate is isolated: no default manifest or previous linked binary is
promoted by this source change.

** Third slice: native cookie components and local FFI qualification

=TimestampRepeater= and =TimestampDelay= are now transparent CST nodes,
with separate source-backed mark/value/unit tokens declared by Scheme.
The graph retains each node's complete raw cookie text and exposes its three
classified fields. Rust decodes those fields into enums and =u32= values;
the handwritten prefix stripping, suffix-byte recognition and numeric-body
slicing have been removed. There is no old-token compatibility branch.

Scheme cookie validation scans only the admitted field once after choosing
the declared prefix; it does not scan the remainder of the line once for each
possible unit. A malformed sign, missing magnitude, embedded punctuation or
extra unit recovers as one lossless trivia field. This is an algorithmic bound,
not an observed endpoint speedup. Date/time component splitting remains an
explicit native-migration debt and is not qualified by this cookie slice.

The grammar and graph tables are regenerated through their existing Scheme
generators using =scheme-timestamp-graph-generate=. They are data projections,
not new Rust recognizers. The public fixture now checks 20 forms, including
leading zeros and magnitudes at/above =u32= maximum. Lexical admission and
typed numeric overflow remain distinct boundaries. Existing timestamp raw,
repeater/warning kind and source ranges must survive selected-program tests.

* 2026-10-04 architecture re-audit: native execution, not Scheme authorship

User direction: remove remaining Rust grammar/semantic execution, not merely
rename it AOT. Audit checkout is =codex/native-org-recovery= at base
=479b2763fa1924385a2df824d029e9ba35341bcd= with the existing dirty migration.
Unrelated changes and upstream runtime/kernel sources are preserved.

The public parse chain is native:
=Org= -> =OrgAotDocument::try_parse= -> =parse_org_aot_with_config= ->
=native_events::parse_events= -> =orgize_parse_events=.
=parse_generated_events= validates and folds admitted events into Rowan; it
is not the former Rust Org recognizer. This does NOT prove the owned semantic
projection is native.

Concrete remaining execution debt:

| Area | Current executable owner/evidence | Required native replacement |
|------+-----------------------------------+-----------------------------|
| Timestamp | =aot_timestamp_projection.rs=: time colon/hyphen splits, point grouping, delimiter pairing | Scheme-owned point nodes, classified time components and explicit range relationships |
| Source switches/header arguments | =aot_block_switches.rs=: quote stripping, value association by offsets, colon subtraction and trimming | Scheme-owned argument/switch nodes with raw/value spans |
| INCLUDE/ATTR | =aot_include_projection.rs= and =aot_projection.rs::keyword_attributes=: quote stripping and key/value association | Scheme-owned option/attribute nodes and value boundaries |
| Headline/TODO/config | =org_aot.rs= document admission builds =effective_config=; =headline_details= invokes generated Rust functions | Native document-scoped directive/config resolution and headline facts |
| Keyword semantics | =org_aot_document_keyword_functions.rs= includes generated word/option/boolean algorithms | Native classified keyword facts, not Rust string scanners |
| Link semantics | =org_aot_link_functions.rs= includes protocol/path/search/abbreviation algorithms | Native link facts with source spans and native document context |
| Citation | =org_aot_citation_functions.rs= includes style/variant string algorithms | Native style/variant fields from the citation recognizer |
| LOGBOOK/CLOCK | =org_aot_logbook_functions.rs= includes line/quote/duration algorithms | Native typed logbook entries and duration components |

| Radio links | =aot_radio_generated_matcher.rs= includes a generated Rust source matcher used by =aot_radio_projection.rs= | Native document-level target collection/matching and match spans |
| Recursive fragments | =aot_inline_fragment.rs= reparses bounded fragments through the same native parser | Single native recursive event/graph ownership where possible; not a legacy Rust fallback |

The build registry =build-support/src/org_aot_functions.rs= contains 48
function IR inputs plus one source matcher. =compile_function_json= and
=compile_source_match_json= generate Rust executors in =OUT_DIR=; the adapters
include them into Rust. Some entries are helper/test dependencies, so this
count is a generator inventory, not 48 independently reachable public calls.
Scheme source ownership and generated-Rust execution must be reported
separately. The current adapters' AOT wording does not qualify native
execution. Remove each adapter, registry entry and obsolete generated-IR
test only after its native replacement has executable source/behavior gates.

Secondary audit candidates also exist outside =aot_*=:
=source_block_references.rs=, =preprocessing.rs=, =progress.rs=,
=property_schema.rs=, =org_contract.rs=, =table_visualization.rs= and related
domain helpers contain string recognizers. Determine whether each consumes
Org source syntax, an already admitted value, or application/export policy
before deleting it. Regex matches alone are not proof of a legacy parser.
Export escaping, filesystem operations, ABI validation and owned-value
conversion are not grammar recognizers and must not be deleted blindly.

Replacement boundary:
- Scheme drives recognition, recovery, lexical values, field association,
  document-scoped syntax/config decisions and semantic relations.
- Extend the existing native event/graph/batch handoff. No per-field FFI
  callbacks, extra compatibility parser, JSON runtime parser or kernel patch.
- Rust retains typed ABI validation, admitted tape decoding, owned memory,
  generic Rowan/graph materialization and optional runtime scheduling.
- Runtime choice changes lifecycle/scheduling ownership only; both features
  use the same Scheme syntax/semantic facts.
- Green generator/IR tests do not replace native FFI consumer tests.
