#+title: Org-to-engine convergence checklist

* Audit scope and ownership

Local source audit on 2026-10-09: Orgize baseline =9d2e9da4= and engine
baseline =3edb3262=. Owned local changes follow those baselines. Org's declared
dependency remains =7449072d=; a capability in the candidate checkout does not
mean that downstream dependency alignment has been admitted.
This checklist distinguishes implementation, deletion and qualification;
creating an API or this document does not close a migration item.

The baseline =languages/org/modules/org-parser/*.ss= contains 7,348 lines:
=event-inline.ss= has 900, =event-strategy.ss= 673,
=event-source-header.ss= 333 and =event-inline-timestamp.ss= 319.
These counts include mechanisms, domain rules, value projections and data.
The two Unicode data tables alone contain 561 lines. They are not all
removable parser machinery; a smaller line count is not architectural proof.

The substantive defect is that POO declarations still require downstream
byte loops, scanner state, container stacks, future-close queries and event
lifecycles. The engine must compile those mechanisms. Org should declare
markers, priorities, boundary policies, node/field roles and domain semantics,
not implement a generic parsing scheduler.

* Existing capabilities versus missing composition

- =src/modules/parser/line-structure-objects.ss= already declares HeadingLine,
  BlockLine, InlineLink, TableLine and ListLine as POO objects. However,
  =src/compiler/line-structure-runtime.ss= projects a Rust syntax table;
  that is not the complete native Scheme declaration-compilation path.
- =source-fragment-objects.ss= and =source-fragment-funs.ss= already provide
  delimited fragments, first splits and reference scans. They do not yet
  express all escape, nested-description and recovery policies required by
  Org's hand-written table and inline scanners.
- =event-fold-future.ss= already implements source-backed future queries and
  caching. The Fold runtime already supports helpers and frames. Extend their
  declaration/composition contracts rather than build another Fold runtime.
- At the audit baseline, the public parser interface exposes Grammar and
  source-pattern/priority projections; consumers import other capability
  modules separately. Define clear public ownership without forwarding
  wrappers or requiring a single enormous facade.

* Engine convergence list

API names below describe responsibilities, not promises of existing APIs.
Every item requires an engine implementation, consumer replacement, deletion
of the old downstream mechanism and executable admission.

** E01 / P0: LineStructure to native Scheme event programs

Evidence: [[file:../../../languages/org/parser.ss][parser.ss]] declares POO rules,
but [[file:../../../languages/org/modules/org-parser/event-strategy.ss][event-strategy.ss]]
still generates block/header/container recognition and event control flow.

Engine: compile admitted line declarations into the existing native event
program, including mode dispatch, opening/closing, prepared state and EOF.
Do not return to generated Rust parsing or add a second interpreter.
Org retains markers, node/token roles, priorities and semantic actions.
Admission: one declaration drives native execution; delete replaced
open/body/close chains. Match events, fields and source spans for ordinary,
missing-terminator and EOF inputs.

** E02 / P0: Container boundaries, future queries and recovery

Original audit evidence: =future-close-scan=, =container-future-condition=,
=special-future-condition= and =latex-future-condition= manually enumerated
parent containers and stopping boundaries in =event-strategy.ss=.
The local candidate below removes that composition and the duplicated
special-block/LaTeX scans; it does not close the entire recovery contract.

Engine: composable named terminators, parent constraints, heading boundaries,
opaque regions and recovery. Reuse existing future-query caches with request
and source-identity isolation. Org retains text-recovery, heading termination
and case policies.
Admission: nested, crossed and absent closes; identical names under different
boundaries. Measure repeated scans and input-size growth. Do not widen timeouts
or reuse a result outside its admitted boundary to manufacture a pass.

** E03 / P0: Nested fragments and recognition/commit failure contracts

Evidence: [[file:../../../languages/org/modules/org-parser/event-inline-link.ss][event-inline-link.ss]]
previously maintained open/separator/failure state, helper calls and cursor
updates. Cloze, scripts and citation affixes also compose nested fragments.

Engine: admitted fragments with boundaries, escape, child rules and failure
recovery; consistent cursor advancement and event commit. Failed recognition
must not leak partial nodes or lose source bytes. Reuse existing helpers.
Org retains permitted description objects, target validity, precedence and
node roles.
Admission: Unicode, nesting, truncation, ambiguity and invalid recovery;
source round-trip, balanced nodes and correct subsequent recognition.
Use a non-Org grammar to prove reuse rather than merely relocate Org code.

** E04 / P0: Compile-time ownership of state, helpers and scopes

Evidence: =org-event-initial= and =org-event-helpers= manually assemble named
slots. =make-org-event-helper= / =make-org-event-strategy= wrap private
initial/forms protocols in =objects.ss=.

Engine: per-rule state types, helper parameters, scope, name allocation and
frame lifetime; reuse =event-fold-state-frame.ss=. Do not promote Org private
wrappers as the generic public API. Org retains request configuration and
domain-state declarations.
Normal authors use POO objects and named pure combinators, not raw alists,
low-level forms or arbitrary callback hooks as their ordinary interface.
Admission: repeated instances, colliding names, recursive helpers and invalid
fields/types; no state leakage between requests. Admit semantic parity in
the existing native AOT and interpreted paths separately.

** E05 / P1: Escape/quote-aware splitting and lexical field scanning

Evidence: [[file:../../../languages/org/modules/org-parser/event-table.ss][event-table.ss]]
previously maintained escape state in =table-row-form=;
[[file:../../../languages/org/modules/org-parser/event-source-header.ss][event-source-header.ss]]
still implements bare/quoted/switch/value/trivia scanning and finalization.

Engine: extend SourceFragment declarations with checked escape, quote,
separator, trivia and source-backed fields. Org retains Babel/header-args
key/switch semantics, table borders and formulas.
Admission: empty fields, trailing separators, odd/even escapes, unclosed
quotes, CRLF and multibyte fields. Delete the old byte loops; do not leave
them underneath new wrappers.

** E06 / P1: Hierarchy, indentation and continuous-text lifecycle

Baseline evidence: =event-list.ss= packed columns/frames and closed list paragraphs;
=event-paragraph.ss= previously managed span state. =event-strategy.ss= also
coordinates footnote, fixed-width, comment and pending-blank transitions.

Engine: indentation/hierarchy, continuous spans, pending trivia, container
entry/exit and EOF composition. Reuse =scan-list-marker= and frame operations.
Org retains markers, tab width, checkbox/counter/tag rules and blank-line
termination policy.
Admission: mixed indentation, deep lists, sibling transitions, trivia recovery
and EOF. Engine owns node balance; delete downstream frame encoding and
duplicated close/finish protocols.

** E07 / P1: Inline priority and trigger-dispatch compilation

Evidence: =event-inline.ss= uses =source-priority-forms= but still combines
trigger bytes, markup/target lifecycles and active scanning paths manually.

Engine: compile trigger classification, ordered choice, active modes and
dispatch; reuse priority projections and prepared byte sets. Org retains
precedence, left/right boundaries and the rule that a matched empty action
suppresses later alternatives.
Admission: matched ambiguity controls, predicates per byte and allocation
counts on dense, sparse and invalid input. One wall-clock sample is not proof.

** E08 / P1: Source views, physical lines and coordinate services

Evidence: [[file:../../../languages/org/modules/org-parser/text-funs.ss][text-funs.ss]]
implements UTF-8 widths, physical lines and prefix/find operations;
=block-line-funs.ss= reconstructs source/value lines for derived content.
These are semantic helper paths; profiling is required before claiming that
the main parser repeatedly scans the whole document.

Engine: source-backed line/slice views, checked search and byte/character
coordinates. Cache ownership must include request, revision and slice identity.
Org retains unescape/unindent semantics and derived-to-original mapping policy.
Admission: CR/LF/CRLF, empty input, no final newline, multibyte and slice edges;
count copied bytes and repeated line construction. Prefer official Gerbil
Unicode facilities for generic mechanisms, but do not move Org entity names
or case/whitespace policies without semantic verification.

** E09 / P1: Stable authoring, compilation and runtime boundaries

Evidence: =runtime-funs.ss= directly imports compiler-owned =run-event-fold=;
consumers combine public, object-module and Org private descriptor imports.

Engine: clear public declaration, compiled-program and request-execution
boundaries with error/version contracts. E01-E08 use this surface; low-level
IR remains engine-owned. Org retains metadata, grammar/semantic registration
and thin invocation adapters.
Admission: ordinary consumers do not call private compiler protocols;
clean SDK public imports, AOT and FFI controls pass without compatibility
aliases or new launcher/process frameworks.

** E10 / P0: Companion closure item: native results and FFI lifetime

Evidence: =src/org_aot.rs= still calls =parse_generated_events= and
=project_syntax_graph=. This is not Org grammar and is outside the line count.

Engine/bridge: native result/view ownership, leases, source identity, release,
error propagation and cross-runtime completion; avoid another downstream
navigation materialization. Org retains request configuration and typed thin
interfaces. Rust/Tokio and Scheme scheduling choices remain supported.
Admission: both runtimes, Rust/Python, release/cancel/shutdown negatives and
source identity. Never hand a thread-bound NativeParsed to arbitrary Tokio
callers without an admitted ownership design.

* Implementation order and deletion policy

1. E01/E04/E09 establish POO declarations to native programs. Do not add another
   generic state machine or replacement framework in Org.
2. E02/E03 establish boundaries, nesting and failure contracts; E05/E06 then
   replace real header/table/list consumers. Each migration deletes its old
   downstream implementation.
3. E07/E08 reduce scanning/allocation after semantics are fixed. E10 remains
   independently required for thin FFI closure; syntax work or pin updates
   cannot establish its completion.

Do not hardcode dates, TODO, Agenda, Contract policies, Babel semantics,
entities or publishing rules into the generic engine. Extract reusable
lexical mechanisms while keeping domain declarations in Scheme language
modules. Copying Org files into the engine and renaming them is not sufficient.
Engine tests own generic controls; Org tests own domain regressions. Avoid
duplicating expensive suites. Use existing Just/native SS owners, not another
shell/JavaScript runner. Full admission still requires both runtimes,
1,000/10,000 concurrent documents, Rust/Python, source/event parity, allocation
and stage observations. Separate cold startup from steady state; do not lower
concurrency, widen deadlines or substitute historical green receipts.
