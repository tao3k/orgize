* Consumer timeout repair

The full consumer catalog now runs under the existing five-second real-output
watchdog. This exposed two deliberately silent negative fixtures whose own
five-second timeout collided with that outer bound. Their fixture-only timeout
is one second. Assertions still require timeout classification, rejected
validation evidence, process-group termination, and child reaping. Production
runtime defaults, successful controls, and the watchdog remain unchanged.

The library's ordinary and ignored counts are explicit candidate inputs and
are checked against its exact libtest catalog before execution. Profiled and
unprofiled feature builds must not borrow each other's historical counts.

The first 1,000-document query retained an obsolete per-document metadata
request assertion: it expected 1,016 calls but observed 32. The source handoff
now sends one event packet and one metadata-plan packet per bounded batch.
Qualification asserts exactly twice the actual packet count for full, hit,
and no-hit queries, while retaining the independent full-projection oracle,
distinct-path inventory, worker counts, and completed-document counts.

* Remaining performance gates and engine work

The 256-document Contract control preserves its 400ms cold-sample maximum.
Rust fails an initial overlapping diagnostic at 582.975834ms and a separate
serial receipt at 475.601917ms. The Scheme serial receipt passes. These
variable samples do not establish a scheduler ranking or close Rust admission.

The complete 2,000-document ledger keeps its 100ms best-of-five gate. Serial
profiled receipts fail at 390.697333ms (Rust) and 236.63525ms (Scheme). Both
still return all 2,000 records and the checked target metadata. The ledger
issues only 64 native requests, not one request per file: batching is present.
It starts 32 host workers against one native owner per domain. Worker wait
sums overlap and must not be reported as elapsed time.

One serial Scheme sample records approximately 185ms of native batch-owner
CPU and a separate, overlapping VM GC CPU interval of roughly 72ms. Its Rust
record projection costs about 2ms in aggregate. Removing that loop or disabling
concurrency cannot by itself satisfy the whole-request gate. The next engine
work is a native, bounded field-projection plan that avoids publishing a full
Org event/index graph for a root-ledger query, with a full-parser semantic
oracle for TODO directives, properties, opaque bodies, ordering, and spans.
This is an engine projection gap, not permission for a second Rust parser.
See [[file:37-engine-convergence-list.org][the shared engine convergence List]].
