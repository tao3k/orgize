* Integrated ownership change

The four private Scheme owners are =text-funs.ss=, =block-line-funs.ss=,
=keyword-funs.ss= and =dir-path-funs.ss= under
=languages/org/v1/modules/org-parser/=. They are included in the normal build
graph, not only a manually assembled test closure.

- Block facts own LF/CR/CRLF splitting, UTF-8 source byte ranges, leading tab
  expansion, common indentation, numbering and custom code-reference labels.
  Literal/fixed-width block annotations consume the same native source ranges;
  dynamic content count/nonblank detection consumes a native plan too.
- Keyword plans own ASCII routing, Unicode word/tag separation, first/rest,
  last-option-wins and boolean classification. Document prescan submits all
  keywords in one counted-field request, not one FFI call per keyword.
- DIR processing uses native input trim/property macro expansion, command
  plans and environment plans in that order. Quote/escape/nesting and malformed
  marker recognition belong to Scheme. Process execution, environment lookup,
  filesystem/path resolution and failure-preserving host effects remain Rust.

The existing identity-bound =ONR1=/=OXV1= native binary framing is reused.
This is not a JSON semantic bridge, an interpreted generated-SCM fallback,
a second Python framework, or a Gambit kernel modification.

Rust block/settings/DIR consumers now admit typed native rows. Their range,
row-arity and framing checks are transport/projection checks, not replacement
Org scanners. PROPERTY duration and ARCHIVE location parsing downstream of
keyword routing are explicitly still open; LINK name normalization and
abbreviation expansion/classification also need the remaining link admission.
