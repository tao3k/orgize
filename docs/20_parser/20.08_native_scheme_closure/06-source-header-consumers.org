* 2026-10-05 native source-switch argument roles admitted on both runtimes

Scheme now emits typed new/continued line-number arguments and the label
format's source-backed content. Balanced double quotes are separated as
lossless delimiter tokens in Scheme; empty labels, single-quoted labels and
unterminated quotes retain their established semantics. Rust no longer pairs
switch names/values by source-range proximity or strips label-format quotes.
It decodes the Scheme-owned field names and numeric values in source order,
including later missing arguments overriding earlier values.

=SourceSwitchValue= retains its existing numeric kind ID but becomes a CST
wrapper; new semantic kinds are appended. These wrappers are not projected
as new public graph records, preserving parent ownership and record IDs.
Both source and example blocks project the typed fields. The new native
admission covers seven fixtures for each block kind, including Unicode and
CRLF, repeated numbering, missing arguments, invalid numbers, empty labels,
single quotes and unterminated double quotes. Switch field ranges must equal
their exact source bytes, and the entire source must round-trip losslessly.

* 2026-10-05 complete native source-header argument and switch extents

This closes the complete source-block header projection unit, not only one
numeric switch role. Scheme owns the parameter extent, each complete argument,
its colon/key/value/raw boundaries, empty values, repeated keys and multiword
values. The shared scanner also emits these fields for dynamic blocks, inline
source, keyword headers and HEADER_ARGS properties. Transparent CST wrappers
do not add public graph records or change record ancestry. Numeric syntax-kind

the catalog. They must not be confused with stable source-order record IDs.

declared numbers/enums and copies the Scheme-declared switch source extent.

quote stripping or header trim remains in this owner. The parser engine,
Gambit kernel and runtime concurrency architecture are unchanged.

** Remaining global semantic ownership audit

The public =Org::parse= route is native Scheme AOT without a legacy Rust
parser fallback. That does not yet mean every owned semantic projection is
thin ABI decoding. The current source audit still finds concrete ownership
work outside this closed unit:

- =aot_projection/document.rs::keyword_attributes= and
  =aot_include_projection.rs=: sort lexical fields, reconstruct colon/raw
  extents and strip quotes. They must consume native semantic declarations;
  do not add another Rust header parser.
- =preprocessing.rs=: MACRO name validation and escaped argument splitting
  remain Rust syntax decisions and need one complete Scheme macro family.
- =aot_table_projection.rs=: cell-content trim and range reconstruction,
  plus formula text trim, remain projection decisions to move into native
  declarations with exact source-span admissions.
- =block_metadata.rs=: source line splitting remains Rust-owned despite the
  existing native =OrgBlockBodyLine= structure; remove redundant reconstruction
  only after preserving code-reference and line-ending consumers.

Attachment storage paths, link resolution, radio matching and runtime/provider
execution must be classified separately from grammar ownership; do not delete
them merely because a broad search finds =trim= or =chars=. Complete global
Org semantic migration remains open until these native families and their
full consumers are admitted. The earlier timestamp/switch benchmark receipts
do not qualify this new program.

* 2026-10-05 complete shared header consumer migration

This completes the shared header family across source blocks, dynamic blocks,
inline source, HEADER_ARGS properties, keyword attributes and INCLUDE options.
Scheme now declares both the full argument source extent and lexical semantic
content. Balanced double quotes have explicit native quote/content nodes;
empty quoted content is an empty native node, distinct from a missing value.
Single quotes, escaped quote bytes and unterminated double quotes retain their
declared literal content. Multiword tails remain in the complete raw argument;
keyword attributes and INCLUDE retain their existing first-lexical-value
semantics. No Rust quote stripping or neighbouring-field reconstruction is
used to make that distinction.

=aot_projection/document.rs::keyword_attributes= and
=aot_include_projection.rs= now consume the same source-ordered native decoder
as the block header owner, selecting =argument-content= instead of the complete
=argument-value=. Sorting, colon subtraction, lexical pairing and quote
stripping are removed from both owners. The new =SourceHeaderValue= and
=SourceHeaderValueContent= wrappers do not introduce public graph records.
Legacy lexical field labels remain source-compatible node-text projections;
they are not a second runtime parser.

** Consolidated remaining migration boundary

The previous audit's keyword-attribute/INCLUDE item is closed by this section.
Global semantic migration is still open; do not present this completed family
as complete Org closure. Keep the remaining work in whole consumer families:

- MACRO definitions and invocations: move name admission, template boundaries,
  escaped argument segmentation and recovery together, including expansion
  consumers; do not merely relocate =preprocessing.rs=.
- Tables: declare cell semantic content/ranges and formula text boundaries
  natively, then admit formula, alignment, query, lint and export consumers.
- Literal block lines: use native line structure while preserving CR/LF/CRLF,
  indentation, code references, numbering, tangle and export behavior; moving
  only =split_block_lines= does not close the metadata family.
- Keyword settings must be classified separately: current prescan trim calls
  and generated =org_aot::keyword_*= helpers are not proof of native-runtime
  Scheme semantic ownership. Audit their actual execution boundary before
  asserting global closure or deleting policy/link-resolution behavior.

Public =Org::parse= and =ParseConfig::parse= still enter native Gerbil events
without a legacy Rust parser fallback. Rust-owned semantic reconstruction
outside that entrypoint remains a separate migration obligation. Every next
family must preserve the complete consumer catalog and both runtime matrices,
not substitute a handful of isolated cases for closure.
