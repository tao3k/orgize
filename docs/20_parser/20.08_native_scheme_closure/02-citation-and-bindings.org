* 2026-10-04 Citation header: delete the Rust IR execution family

This slice removes real executable ownership, not just the adapter wording.
The native Scheme citation scanner now records the first style separator and
the admitted colon while performing its existing validity scan. It emits
=OrgCitationHead=, =CitationStyle= and optional =CitationVariant= with exact
source spans. Consecutive candidates reset styled/variant state. Empty style,
empty/repeated adjacent separators, whitespace in the header, missing keys,
escaped keys and unclosed candidates retain the existing recovery behavior.
Nonempty multi-part variants and Unicode headers retain their admitted values.

The old execution chain is deleted:
- =src/org_aot_citation_functions.rs= and its =org_aot.rs= wrappers/import;
- =citation_style= / =citation_variant= build registry entries;
- =languages/org/v1/modules/org-elements/citation-functions.ss=;
- =generate-citation-ir.ss= and the two committed citation IR files;
- the citation IR-identity test/import in =t/org-elements-module-test.ss=;
- the integration suite's generated-Rust includes and direct function oracle.

The 7 existing citation consumer cases remain registered. The former IR-only
header case now exercises =Org::parse= and its owned AST. The registry is
reduced from 48 to 46 function inputs; the radio matcher remains unchanged.
There is no compatibility branch or new per-field FFI export.

Rust reads Scheme-classified =style= / =variant= fields. Absent fields decode
the public AST's existing ="nil"= / empty sentinels; Rust does not inspect or
split header source. Global prefix/suffix positioning now uses native graph
ranges rather than header-length arithmetic. The =head= field is intentionally
the contiguous native header, e.g. ="[cite/text:"=, not the former synthetic
="[cite/text:]"= assembled from separated delimiter tokens. Its consumer
expectation was updated explicitly, not by mass snapshot acceptance.
