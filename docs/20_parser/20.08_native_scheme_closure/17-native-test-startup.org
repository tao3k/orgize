* Findings and repair

Native gxtest prepares all module imports before emitting =HARNESS=. Its source
entry recursively expands relative imports; even a compiled suite interface
still imports compiler phase interfaces. Import tracing observed 1,553 import
boundaries, an approximately 2.787-second top-level import, and fresh grammar
artifact generation. A fresh untraced directory passes the owner suite; the
previous five-second silent-startup failures remain negative evidence. This
does not establish one stable timing cause for every historical startup failure.

=t/org-native-closure.ss= statically imports the existing standard Gerbil test
suite values. It constructs =TestHarness=/=TestModule= and uses =test-run!=;
there is no replacement assertion framework, runtime source expansion or
semantic JSON transport added. The =--failure-control= mode deliberately fails
one standard assertion and must return 42, not an apparent successful harness.
The control confirms the standard framework can print =HARNESS-OK= after a
failed check: exit status, final =FAILED=/=OK= and failure markers are therefore
mandatory. No library/kernel patch or altered assertion semantics hides this.
The ordinary entry accepts no filters and executes the whole selected catalog.

Executable linking exposed missing explicit test roots: the graph/catalog and
Query build interfaces, parser/Elements test helpers, and fixture owner. These
are built before linking. Generator coverage is retained; typed Rust query
projection is not a second raw Org parser.

Gerbil emits C beside user static SCM when linking executables. Writing next to
shared dependency checkouts was rejected by the sandbox. The bridge's existing
compiler-graph adapter now stages the exact user runtime dependency artifacts
into the chosen build directory. It accepts a compiled =.ssi= root, copies SCM
opaquely, does not evaluate generated SCM, and never replaces a compiled owner.
Orgize passes an explicit bridge checkout to this owner and invokes only the
unified =gerbil compile= command. New SDK/source identities require a fresh
qualification output directory; a cached output is not fresh-source evidence.

Darwin also exposed a native linker setup gap: =CC= alone does not select the
Gerbil executable linker. =GERBIL_GCC=/usr/bin/cc= is now scoped to Darwin along
with =SDKROOT= removal. Normal native executable linking is used; forcing a
fully static system link fails with missing =crt0.o= on Darwin. This is not a
runtime compatibility fallback or a Gambit kernel change.
