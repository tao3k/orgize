* First slice: opaque Elements inside list Items

The official Org manual describes indented block constructs as belonging to
list Items: [[https://orgmode.org/manual/Plain-Lists.html][Plain Lists]].
The implementation reuses the existing declared source/example/comment/export
rules, block headers, closing admission, body masking and recovery. It adds no
Org recognition in Rust and no generic engine primitive or kernel change.

The confirmed baseline parses an indented example block as an Item paragraph,
even recognizing underscores in its begin/end markers as inline subscript
Objects. The new expected AST requires an OrgExampleBlock inside the first
Item and a subsequent sibling Item. A freshly compiled baseline suite fails
that exact AST expectation in
=target/list-opaque-syntax-20261004/baseline/structural-test.log=.

An earlier import-only aggregate run was green because it could resolve an
older compiled child test suite. That run does not qualify the new case.
=scheme-structural-event-test= explicitly compiles the edited suite into an
isolated output overlay before native gxtest, then requires MODULE-OK,
HARNESS-OK, final OK and no error markers.

The Scheme list continuation now attempts declared opaque Elements before
paragraph text, while retaining the owning Item. Its paragraph closes only
after successful block admission; a rejected opener has no transition side
effects. Six regression cases cover exact offsets/ancestry, all four opaque
families with UTF-8/CRLF and sibling Items, an unterminated EOF closing line,
unclosed input before a headline, a dedented block outside the Item, and exact
indented standalone source-header ranges.

Candidate compilation and validation status must be recorded below before
this slice can be called locally qualified. Native staging, linked FFI,
full consumers and performance gates remain separate from Scheme AST tests.
