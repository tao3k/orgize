* 20.06 Scheme Grammar to Rowan Cutover

The Org syntax declaration belongs in a versioned Gerbil language pack.  The
normal Rust consumer must depend on the generated Org module and the generic
=gerbil-parser-rowan= runtime only.  It must not invoke Gerbil at parse time,
copy the Rowan sink into orgize, or retain a second Rust grammar as a fallback.

** Baseline and authority

- Use the named upstream =org-element.el= revision only as a comparison
  reference.  The executable element inventory belongs to
  =languages/org/v1/modules/org-elements/catalog.ss=; its generated Rust projection and
  Git-tracked Org corpus are the test inputs.  Emacs Lisp is never an
  implementation or Cargo fixture.
- Maintain =languages/org/<version>/grammar.ss=, the Org-owned Scheme event
  strategy modules, and their AST tests as one language pack. The Git-tracked regression source is
  =tests/fixtures/org-elements/representative.org=; a complete versioned
  =fixtures.ss=/=corpus/= and element/object coverage remain cutover work. The
  Scheme pack owns Org precedence, ambiguity, syntax kinds, fields, recovery,
  and all context-sensitive recognition decisions.
- Generate and commit immutable Rust tables from that pack.  Cargo consumers
  use those tables without =gerbil.pkg=, an installed Gerbil, or build-time
  Scheme.  Regeneration is an upstream development/release action.

** Current implementation

=languages/org/v1/grammar.ss= owns Org syntax kinds and
=modules/org-parser/event-strategy.ss= composes the Scheme event algorithm.
The shared =parser.ss= POO block declarations supply markers to that
algorithm; they are not a second runtime parser. Gerbil executes the same
event strategy in tests and AOT-lowers it through gerbil-parser and
gerbil-scheme-rust into a Rust function consumed by Rowan. Cargo parsing
requires neither Gerbil nor =gerbil.pkg=. Source-backed event AST tests and
graph/roundtrip fixtures verify this path.

=modules/org-elements/catalog.ss= owns the Element/Object inventory and
=graph-shape.ss= owns source-backed projection fields. The public
=Org::parse= now calls the Scheme-event AOT/Rowan parser; the handwritten
=src/syntax= parser has been removed. This does not by itself close context,
malformed-input, configuration, semantic projection, or performance parity.

The Scheme event AOT also recognizes inline source blocks and inline Babel
calls, including balanced body delimiters and optional header fields. Their
language/name, body/arguments, and header values are source-backed graph
fields; malformed or incomplete forms remain literal text. Focused Scheme AST
and Cargo graph tests cover these objects through the public AOT path.

** Original upstream engine requirements

The generic upstream engine owns typed event IR compilation and Rowan
construction, not Org recognition. These were the gates for the public parser
swap. The current status and remaining semantic/performance closure are in
=20.07_complete_org_cutover_audit.org=:

1. Complete Org-owned Scheme context, restriction, configuration, and
   property algorithms in the event function; a typed catalog name alone is
   insufficient. The generic Rowan sink remains in gerbil-parser.
2. The generated runtime must preserve malformed input with explicit recovery
   nodes/diagnostics and exact UTF-8 byte ranges, including CRLF and missing
   end delimiters.  A generic all-TEXT success is not admission.
3. Generated typed kinds and fields replace =src/syntax/kind.rs= and the
   handwritten parser-facing =src/syntax/*.rs= modules. The public =Org=
   facade and semantic/export clients must consume the AOT graph; compatibility
   with an incorrect old consumer is not a gate.

** Cutover gate

For each pinned corpus case, compare the old parser and, where applicable,
the pinned =org-element.el= reference with the Scheme-authored AOT product:
acceptance/rejection, tree hierarchy, field boundaries, diagnostics, and
exact source roundtrip. The old parser is evidence, not an authority; record
source-backed intentional changes rather than forcing incorrect parity.
Cover every upstream element/object kind, affiliated keyword,
configuration-dependent behavior, malformed/recovery case, and real Org guide
fixture. Continue expanding this gate after deleting the old parser; deletion
does not by itself establish full semantic or performance parity.

Run performance scenarios on representative Org documents and pathological
nested/ambiguous inputs with the ASP Rust Dev Gate.  Record throughput,
allocation, and peak memory against main; do not weaken existing thresholds
to absorb a generated-engine regression.

Only after the complete differential and performance gates pass should the
handwritten Rust lexer/combinator/element/object parser be removed.  Keeping
both as a runtime selection path would create two grammar authorities.
