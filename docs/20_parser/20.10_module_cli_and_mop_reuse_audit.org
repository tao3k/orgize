* Correction to 20.09

This record supersedes 20.09's API/build/test ownership recommendations.
The previous =funs.ss= public entry was not Yuanxu's native =func.ss= role.
Compensating with business =library-roots= inventories repeated dependency
ownership already provided by =yuanxu! :load-modules=.

[[file:../../init.ss][Root init]] selects the three Org Modules and native C Module. Their
=func.ss= roles import ordinary implementation units; =config.ss= owns
profiles; =interface.ss= declares the Module. Yuanxu admits roles and derives
the native source closure. OrgContract is fully selected through these roles.
No business =library-roots=, compatibility API, source scanner, or alternate
loader remains. Explicit Build roots are retained only for foreign compiler
leaves and their actual platform options.

The dependency direction is Parser, then Element, then Contract, then native
integration. The tape consumer composes these capabilities and therefore lives
in =bindings/c/event-tape.ss=. It does not belong to the base Parser Module.
Cross-module sources use admitted owner identities. Foreign clock definitions
are compiled as native leaves; profiling accepts clock procedures so the
functional role remains interpretable. C entrypoints and profiling fixtures
supply the same native monotonic/thread CPU clocks.

* Reuse rather than another object system

Contract, Element and Parser business data use POO =define-type= and =Record=
with native union, list, enum, optional-field and scalar contracts.
Constructors call native =validate=. Yuanxu's =defpoo-object-family= generates
accessors, as it does in Parser. Handwritten structural validators and repeated
accessor definitions have been removed.

Org graph declarations construct Parser's existing graph node/field objects.
The duplicate Org graph Types, constructors and conversion pass are removed.
Native Parser graph-query contracts remain shared dependencies. Orgize retains
Org-specific catalog membership, query bounds, source semantics and grammar
constraints. Lazy strategy programs are not forced merely to test membership.
Generic/MOP reuse follows the owning protocol; introducing a new dispatch
framework would repeat the same mistake.

* Native command ownership

- =gerbil deps --install= owns package installation and transitive dependencies.
- =gerbil build --optimized= runs the Parser-backed fold producer, the standard
  generated-package build adapter, native Module build and program staging.
- =gerbil test -v 5 orgize-test.ss= owns discovery and execution of exported
  standard Suites. Orgize supplies only the roster and fixture lifecycle.

The generated fold package retains the Parser emitter's exact unit catalog.
An empty explicit Module selection is sufficient for those compiler-owned
roots; artificial Module role files are unnecessary. The duplicate Org
bootstrap, dependency installer, closure runner, executable test projection
and Core lifecycle tests have been removed.

CI runs the Scheme lane once per OS, uses the native commands above and checks
an intentional failing Suite's exit status. The generic output observer is
retained solely to preserve the existing five-second idle-output requirement.
It does not discover, select or execute Suites. The source build now uses 2 GiB/600 seconds, as authorized after the local
qualification below. Tests retain the 1 GiB/120-second fence.
