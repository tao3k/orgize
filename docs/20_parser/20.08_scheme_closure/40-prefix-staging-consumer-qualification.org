* Official byte codec candidate

The native tape's handwritten quotient/modulo writer and multiply/add reader
are replaced by Gerbil's checked =u8vector-uint-set!= and =u8vector-uint-ref=
with explicit little endianness and width. Generic byte access supports the
wire format's unaligned fields; no host-native aligned integer cast is used.
The original exact, nonnegative, width-bounded value check remains because
the official generic writer alone truncates over-width values.

The existing semantic suite adds an independent arithmetic byte oracle for
both token u64 fields, including zero, byte boundaries, 32-bit boundaries,
the high u64 bit and maximum u64. Negative, fractional and overflowing values
must still fail. The candidate has a separate =program-official-codec= stage;
baseline Rust/Scheme executables above remain unchanged. This is not yet a
measured whole-parser performance gain or complete 100ms admission.
The candidate passes all 178 native cases, 12 suites and exit-42 control,
including the new arithmetic-oracle assertions. The executable's copied
static tape source matches =program-official-codec= byte for byte.
