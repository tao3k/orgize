* Implemented algorithm changes

- Prepare whitespace-separated query terms and field predicates once per
  query rather than normalize each term for every candidate field.
- ASCII-insensitive matching borrows fact strings without allocating
  lowercase haystacks. SIMD candidate search has a linear comparison budget;
  repeated-prefix inputs fall back to prepared KMP. Per-string search has
  an O(N + M) worst-case bound and preserves non-ASCII bytes unchanged.
- Parse every source through the same native owner. Apply predicates to
  admitted fact values before constructing selectors, ancestry strings and
  line positions. No raw-source prefilter may skip native parsing.
- Compute display paths and structural selector prefixes once per document.
  Line indexes and sibling ordinals are document-local lazy projections,
  not a persistent result cache or semantic runtime state.
- Do not clone heading fields when no task fact is emitted.

The private =query_match.rs= is mechanical filtering of admitted facts,
not an Org parser, public DSL or Scheme policy replacement. A native control
matches Scheme-derived =todoType=Done= although DONE is absent from the
raw source. Filtered projection is compared with the complete native
projection, including order, fields, source ranges and selectors.
Existing full-index APIs retain their complete output.

* Next architectural owner

Production Query's four host workers share a process-local native owner.
The Rust feature has one bounded queue and one Gerbil-owning thread;
the Scheme feature admits work to its native actor. Four caller threads
do not establish four independently executing native domains.
The existing benchmark's 1/4/8 domains are independently exec'd native
processes, not concurrent entries into one VM. This admission harness
must not be described as a production multi-domain Query pool.

The parser's =src/compiler/event-fold-runtime.ss= still implements state
lookup with =assq= and each state update with a complete =map= over the
state list. This is an O(S) lookup/update allocation candidate, not a
measured proof of the GC root cause. Nested helpers, overrides, failure
paths and branch isolation must retain their persistent-state semantics.
The Org strategy also prepares helper descriptors for each invocation.

The next native owner change should prepare immutable helper/state layouts
in Scheme, then compare persistent indexed state or compiled accessors
against the existing owner with exact event/graph artifacts and native
controls. It must not replace the functional public POO strategy interface
with a mutable host DSL, add global stale caches or patch the runtime kernel.

Standalone Rowan/Python admission, clean published dependency bootstrap,
platform CI, the historical Query tail and whole-parser grammar closure
remain separate gates. The previously qualified default manifest is not
switched. No commit, push, PR creation or remote update is performed.
