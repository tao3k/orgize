#+title: Request completion isolation and bootstrap cache boundary

[[file:../20.08_scheme_closure_ledger.org][Native Scheme closure index]]

* Runtime change and unchanged gates

The Contract scenario's limit is 25 milliseconds, not 25 seconds.
Earlier profiles place most of the tail in admission/completion transport,
not the approximately 1--2ms Scheme Fold interval. This candidate separates
each request's completion mutex from the bounded admission queue mutex.
Caller-owned request storage remains live until completion; the sole native
Scheme actor still owns Scheme ABI and GC access. FIFO capacity remains 64,
both runtime features remain available, and no kernel, timeout, Release
optimization, fixture or concurrency setting changes.

Notification publishes status/results under the request mutex. Queue removal
precedes notification, so a returning caller can release its stack storage.
Terminal failure notifies both the active request and queued requests and
broadcasts to capacity waiters. Any nested acquisition is queue then request;
the caller's completion path never acquires the admission mutex.

* Bootstrap source versus native object cache

Generated =.scm= can be versioned as explicit bootstrap source, accompanied
by compiler/source provenance and a regeneration equality gate. Gerbil's
own bootstrap follows this pattern; the pinned bridge already tracks
=scheme/generated/native.scm=. This can avoid repeating Gerbil expansion,
not eliminate Gambit/C compilation or accelerate already-AOT request execution.

This build reuses generated module C, but the package header digest is added
to every module's C compiler options. Changing the private runtime header
therefore invalidates all 165 module objects; the observed compile-object
batch takes 101,121ms. This is build-time invalidation, not a 25ms request.
The upstream native-build owner should admit explicit per-module transitive
header dependencies and retain complete archive identity. Removing header
hashes, reusing stale ABI objects or making Orgize maintain another compiler
pipeline is not acceptable. Target/toolchain-specific =.o/.a= reuse belongs
in a verified content-addressed build cache or release artifact, not an
unqualified source bootstrap. No cache-owner implementation was changed here.

Whole-parser owned GPA1/result lease migration, new-identity Python admission,
and both complete runtime matrices remain separate unresolved gates.
