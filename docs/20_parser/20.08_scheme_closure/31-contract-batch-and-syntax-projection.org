#+title: Contract batch plans and consumer-specific syntax projection

[[file:../20.08_scheme_closure_ledger.org][Native Scheme closure index]]

* Root cause and implementation

The scenario budget is 25 milliseconds. No deadline, fixture, concurrency,
Release profile or Gambit kernel is changed. Completion-mutex isolation alone
did not close this gate: repeated native requests multiply admission and
completion scheduling exposure even when individual Scheme work is cheap.

Contract extraction previously requested the full Babel source-block record.
That computed default headers, result/execution policies and tangle plans that
Contract never consumes. Contract validation also projected that catalog twice.
The new private syntax projection carries only source identity/range, kind,
name, language, parameters and value. Contract and syntax lint use it; Babel
retains the complete existing projection and results. Both projections use the
same monomorphized traversal, preserving scope, order and nested containers;
there is no second parser, tree, scanner or compatibility fallback.

The Scheme owner now admits ordered language/name/parameter triples in one
=contract-block-plans= value request. It returns role, normalized source name,
named assertion identifier and explicitly optional name/severity parameters.
Parameters are tokenized once per block. Rust checks row counts, arity, closed
roles and presence flags, then uses call-local typed values; source grammar
remains Scheme-owned. An empty catalog issues no request. Validation shares
one planned catalog between registry extraction and diagnostics.

This is not cross-document memoization. Request completion profiling adds a
physical native request count, independent of duration observations. The
profiling-disabled path still contains no clocks or collector operations.

* Remaining structural latency work

Batching block metadata removes one repeated crossing family, not all 39
crossings. The next owner boundary must compile the complete document-local
Contract facts (section properties, kind/scope/severity, block roles and
query/expectation plans) inside Scheme and return a typed aggregate once.
Rust should admit that result and perform explicit host effects, rather than
walking a metadata dependency chain through synchronous scalar requests.
That aggregate must preserve source identity, ordering, absent/invalid values,
query evidence and lifecycle ownership; it cannot be a Rust grammar rewrite.

Long jobs on the single Scheme service can still block short jobs. Bounded
cooperative work/admission and explicit backpressure are a separate scheduler
design gate. Shorter compute and fewer handoffs reduce exposure, but do not
guarantee a 25ms wall-clock deadline on an overloaded desktop OS. Neither
spinning waiters, hiding queuing time, reducing test callers nor changing the
deadline closes this architecture boundary.

The refactor's module gate now passes in a focused scanner run. Owner
=mod.rs= files contain declarations/exports only; implementations live in
=org_contract/core.rs= and =source_blocks/traversal.rs=. The benchmark source
corpus follows the moved implementation rather than a thin facade.
Both five-target optimized Release links finish. Intermediate refactor
failures (module layout, moved benchmark corpus path and an unused import)
are repaired. The final import cleanup is admitted by Release source checks
for tests, benches and examples in both runtime features, with the production
library warning gate passing. These source checks are not runtime executions;
linked observations below precede only that unused-import deletion.
