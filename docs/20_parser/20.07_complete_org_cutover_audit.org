#+title: 20.07 Complete Org Parser Cutover Audit
#+startup: overview

* Verdict

The public =Org::parse= and =ParseConfig::parse= paths use the Org-owned Scheme
event algorithm AOT-compiled to Rust/Rowan. The handwritten =src/syntax= parser
and its typed-syntax export API have been removed. Ordinary Cargo consumers do
not run Gerbil or consume Python parser artifacts.

The Scheme source, AOT event IR, Rowan tree, and Element graph are the parsing
authority. Org-specific radio matching is a POO strategy in the Scheme
Elements module, lowered to a Rust function by the generic AOT backend. Rust
only slices already-parsed Objects and projects Link AST values; the displaced
handwritten Rust matcher is not compiled or exported.

The current Orgize PR #18 candidate pins gerbil-parser PR #13 at
=4f6d9d67a069d823cfabc33511783b58017e08b3= for both Scheme and Cargo.
The graph index supplies linear nearest-matching-ancestor projection; Orgize reuses it
for headline scope instead of walking parent chains in separate Rust paths.

Org Element queries now admit the Scheme POO headline properties =title=,
=raw-value=, =priority=, =tags=, and =todo-keyword= in consumer-authored AOT
packs, including bounded =contains= matching. The Cargo executor reads the
Scheme-AOT headline results or the same Element graph; it does not parse a
second headline grammar. =#+TAGS= now lowers through an Org-owned Scheme
source-event helper into Rowan group, name, separator, and shortcut nodes.
The old Rust text parser in =settings.rs= is removed; Rust only projects
source-backed graph fields into the public typed =TagDefinition= shape. New
syntax kinds append to the grammar table so existing Rowan kind IDs stay
stable across this addition.

Native Gerbil execution is a separate performance candidate, not an implicit
property of the Cargo AOT path. The current Scheme =run-event-fold= entry
interprets the admitted strategy; compiling that executor to C and calling it
through FFI would not specialize the Org event transitions. The existing
=orgize-native= C ABI evaluates contracts, not parser events. A serious native
parser comparison requires a specialized C lowering of the same Scheme IR and
one bounded, bulk event transfer per document, then source-range parity and
matched single-document and 2,000-document throughput receipts including
Rowan/Graph projection. Gerbil actors may schedule native work, but Rust AOT
does not run the Gerbil runtime, and concurrency alone is not evidence of
faster CPU-bound parsing. Do not retain two production parser paths merely to
keep an unqualified benchmark candidate.

earlier head after all 48 fixture documents gained
TAGS group and shortcut declarations under the existing 45 ms gate. This
is a runtime path receipt, not a TAGS-only microbenchmark or build-latency
receipt. The exact-head platform CI above is the release-gate evidence for
the current candidate; these earlier fixture and query receipts remain local.

* Remaining ownership work

** Semantic regression ledger

The default-feature serial integration target has no failing tests. All
five =semantic_ast_projects_radio_links= cases now exercise the Scheme POO
source-match strategy through the AOT-generated function, including longest
target, duplicate declarations, plain text, and opt-in parsed-object runs.
Table formula assignments, flags, and references are Scheme-owned and covered
by structural AST tests. Do not weaken these gates or approve =.snap.new= files
wholesale when further grammar nodes are added.

Before a performance claim, benchmark table-heavy parsing, radio-link
projection, and document projection against the prior AOT head. Build latency
is also an open gate. At an earlier slice, a Scheme-authored shared branch
continuation kept the event IR at 1.97 MB. The generic AOT backend's static
future-scan macros reduced generated Rust to 5.43 MB / 75,480 lines, from the
previous 5.65 MB / 80,916 lines and the original 8.68 MB / 112,824 lines. The backend
validates the explicit handled marker and emits the continuation only on the
normal unhandled path; it is not an error-recovery fallback. A standalone
5,000-parse comparison produced the same 58,510,000 events. Two local
old/new runtime pairs took 198.2/92.6 s and 159.7/106.1 s respectively;
the machine's concurrent load varied, so these are non-regression evidence,
not a portable speedup claim. Optimized standalone =rustc= compilation took
519 s under load, which is not comparable to the earlier 274 s measurement;
compilation latency remains an open gate. The earlier locked Orgize
Release query scenario passed its 45 ms gate, but
these historical local measurements are not cross-platform CI closure. Integration and
benchmark targets reuse the library's compiled event entry instead of
including duplicate generated
copies. Distinct Cargo feature sets still recompile the large library function;
runtime parallelism does not solve that compiler cost. The generic event AOT
backend still needs further bounded code-size reduction
with unchanged source-range and throughput receipts.

The =benches/parse.rs= dense-table fixture now exercises 128 tables with eight
rows and a formula each, timing parse and document projection separately.
A short host-local ten-sample smoke run on the current pin produced wide
5.024–9.515 ms parse and 2.037–3.443 ms projection intervals. This checks
that the benchmark executes; it is not a matched old/new comparison or a
performance improvement claim.

The subsequent backend pin lowered byte-set predicates with 16 or more values
to typed 256-bit masks. On the same checked-in Org event IR, generated Rust was
5,271,909 bytes / 73,903 lines, versus 5,427,404 bytes / 75,480 lines at
the preceding pin. The 5,000-parse standalone harness again emitted
58,510,000 events on both versions. Two host-local old/new runtime pairs were
148.4/139.1 s and 147.7/128.5 s; these are not portable speedup claims.
The optimized harness binary grew from 1,340,432 to 1,403,000 bytes, so
binary size remains a second-order cost to watch. The full default Orgize
Cargo suite passes with the new exact backend pin; optimized build latency
and the broader parser/projection benchmarks remain open gates.

At parser-code commit =66d93fb=, Scheme =event-source-header-forms= calls one
Scheme-owned =source-header-span= helper from block, keyword, INCLUDE,
property, and inline source contexts, instead of expanding the same state
machine at each call site. With the same pinned AOT backend, checked-in event
IR changed from 2,435,269 to 1,720,411 bytes. Generated Rust changed from
6,409,267 bytes / 87,854 lines to 4,565,808 bytes / 65,676 lines.
A matched host-local Criterion run over 1,000 source headers found no
statistically significant runtime change (p = 0.75); the size reduction is
established, but neither a throughput improvement nor a portable build-time
improvement is claimed. The same-head Release plan-ledger gate passes locally.

generated forced-inline helper, and repeated line-end offset loops call

=9fd3ef0= pin generated 3,965,804 bytes / 57,317 Rust lines; the

head passed at 73.30 ms). The forced-inline repair subsequently passed the

The Rust TODO declaration lint now consumes AOT-projected keywords rather than
rescanning =#+TODO= and maintaining a second =begin_/end_= block state.
Priority-cookie lint visits AOT section and inlinetask headings and takes
their level from the AST rather than recognizing headlines by raw star scans.
Rust retains the typed duplicate/range checks and diagnostic formatting.
Regressions cover pseudo-directives and pseudo-headlines inside source blocks.
The Babel CALL reference target is now a Scheme-emitted =BabelCallName= token
and graph field. Rust no longer strips =#+call:= from an already-projected
value or splits its target on punctuation. A shared Scheme keyword-value
helper also collapses repeated TITLE, TAGS, INCLUDE, ATTR, HEADER, PROPERTY,
table-formula, and CALL value dispatch. Against the prior =57,317=-line AOT
product, the new event IR is 1,666,505 versus 1,720,411 bytes and generated
Rust is 52,482 versus 57,317 lines (3,601,759 versus 3,965,820 bytes).
The naive inlined Babel branch alone had reached 60,937 lines before the
shared-helper revisions. These are reproducible code-size receipts, not a
runtime speedup claim. The current local Release gates remain unchanged;
the exact =f5a1ac1= Windows gate first failed at 103.2245 ms against the
unchanged 100 ms limit. Its automatic diagnostic rerun passed at 83.8839 ms,
and rerunning the failed job on the same head passed at 81.9714 ms. The other
four exact-head jobs passed. This is a marginal and variable batch gate, not
evidence that the first failure disappeared or that the generated parser is
103 ms per document.

The plan-ledger Criterion scenario now separates generated events,
events plus Rowan, and the full AOT graph for the same 2,000 in-memory
documents. On one macOS host, a 30-sample event-only run centered at
7.7801 ms for all 2,000 documents; a preceding-head 10-sample run centered
at 7.8007 ms. Ten-sample current-head runs centered at 18.540 ms for
events plus Rowan and 32.432 ms for the full AOT graph. Host variance was
large across repeated short runs, so these receipts locate stages and
establish a microsecond-scale per-document order of magnitude, not a
statistically proven speedup or cross-platform performance guarantee. The
Windows batch gate additionally includes 2,000 file reads and semantic
projection, and still needs a more stable margin below 100 ms.
The remaining LOGBOOK path takes its body envelope from the AOT drawer graph.
Lifecycle line-kind recognition now calls a Scheme-owned pure function lowered
to Rust AOT, with Scheme IR and alternate-prefix regressions. One grouped
Scheme rule table drives the runtime =ormap= classifier and a generation-time
=foldr= that produces the allocation-free Rust AOT branch chain; the
canonical function IR and generated Rust are unchanged by this source cleanup.
Rust still trims
list markers and interprets quoted states, timestamps, links, and durations.
This is typed lifecycle interpretation, not a second block parser; moving
value spans into Scheme-owned graph fields requires a focused design and
line-level regression coverage. This unpushed slice locally passed all 13
Scheme modules, locked all-target/all-feature Rust tests, strict Clippy, and
the three Release gates; its 2,000-file plan-ledger gate measured 53.089 ms
best-of-five on this macOS host. It has no exact-head remote CI receipt.
Dynamic-block content counting now uses the
Scheme graph's closing-line range, rather than assuming the last raw line is
the closer; it still interprets content after AOT block classification.
FEEDSTATUS drawer body extraction now uses Scheme graph header-trivia and
closing-line ranges; Rust retains value trimming, readability checks, and
entry counting. A CRLF regression retains a body line equal to the drawer
name rather than deleting it as a second pseudo-opener. This does not
migrate the separate LOGBOOK lifecycle value interpreter or claim full Org
conformance.
The Org query content renderer no longer treats =#+begin_src= or
=#+begin_example= text prefixes as blocks. It preserves source/export block
content only from Scheme-AOT =block= facts; list text not yet classified as a
nested block is compacted as ordinary text. Recognizing such nested blocks is
a Scheme parser coverage item, not a Rust output-side fallback.

* Acceptance

The cutover is complete only when the Scheme suite, full Rust workspace test
matrix, strict policy, source-roundtrip/graph checks, consumer fixtures, and
current AOT performance gates pass at the exact PR head on required platforms.
An individual green fixture or a decreasing failure count is progress, not
completion.

The tracked =.snap= files are AST and consumer regression baselines, including
four direct Scheme-to-Rowan =GraphRecord= snapshots. Do not delete or approve
them merely to make migration tests green. A changed graph snapshot requires
review of kind, fields, ancestry, source ranges, and the source-roundtrip
assertion; generated =.snap.new= files remain unapproved candidates. Numeric
=syntax_kind= changes alone can be accepted only after confirming the semantic
graph is otherwise unchanged. The bare-AST snapshot was reviewed and updated
for Scheme-owned exact list bullets, a description body's separator-free text,
an unnamed source block's absent =NAME=, and coalesced contiguous plain text;
explicit assertions cover the first three. Passing local integration tests do
not establish complete Org-mode coverage or cross-platform release readiness.
