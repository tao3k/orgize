#+title: 20.07 Complete Org Parser Cutover Audit
#+startup: overview

* Verdict

The public =Org::parse= and =ParseConfig::parse= paths use the Org-owned Scheme
event algorithm AOT-compiled to Rust/Rowan. The handwritten =src/syntax= parser
and its typed-syntax export API have been removed. Ordinary Cargo consumers do
not run Gerbil or consume Python parser artifacts.

The Scheme source, AOT event IR, Rowan tree, and Element graph are the parsing
authority. Org-specific radio matching is a POO strategy in the Scheme
Elements module, lowered to a Rust function by the generic AOT backend. Rust
only slices already-parsed Objects and projects Link AST values; the displaced
handwritten Rust matcher is not compiled or exported.

The current Orgize PR #18 candidate pins gerbil-parser PR #13 at
=4f6d9d67a069d823cfabc33511783b58017e08b3= for both Scheme and Cargo.
The graph index supplies linear nearest-matching-ancestor projection; Orgize reuses it
for headline scope instead of walking parent chains in separate Rust paths.

Org Element queries now admit the Scheme POO headline properties =title=,
=raw-value=, =priority=, =tags=, and =todo-keyword= in consumer-authored AOT
packs, including bounded =contains= matching. The Cargo executor reads the
Scheme-AOT headline results or the same Element graph; it does not parse a
second headline grammar. =#+TAGS= now lowers through an Org-owned Scheme
source-event helper into Rowan group, name, separator, and shortcut nodes.
The old Rust text parser in =settings.rs= is removed; Rust only projects
source-backed graph fields into the public typed =TagDefinition= shape. New
syntax kinds append to the grammar table so existing Rowan kind IDs stay
stable across this addition.

Native Gerbil execution is a separate performance candidate, not an implicit
property of the Cargo AOT path. The current Scheme =run-event-fold= entry
interprets the admitted strategy; compiling that executor to C and calling it
through FFI would not specialize the Org event transitions. The existing
=orgize-native= C ABI evaluates contracts, not parser events. A serious native
parser comparison requires a specialized C lowering of the same Scheme IR and
one bounded, bulk event transfer per document, then source-range parity and
matched single-document and 2,000-document throughput receipts including
Rowan/Graph projection. Gerbil actors may schedule native work, but Rust AOT
does not run the Gerbil runtime, and concurrency alone is not evidence of
faster CPU-bound parsing. Do not retain two production parser paths merely to
keep an unqualified benchmark candidate.

* Remaining ownership work

** Semantic regression ledger

The default-feature serial integration target has no failing tests. All
five =semantic_ast_projects_radio_links= cases now exercise the Scheme POO
source-match strategy through the AOT-generated function, including longest
target, duplicate declarations, plain text, and opt-in parsed-object runs.
Table formula assignments, flags, and references are Scheme-owned and covered
by structural AST tests. Do not weaken these gates or approve =.snap.new= files
wholesale when further grammar nodes are added.

projection, and document projection against the prior AOT head. Build latency
is also an open gate. At an earlier slice, a Scheme-authored shared branch
continuation kept the event IR at 1.97 MB. The generic AOT backend's static

5,000-parse comparison produced the same 58,510,000 events. Two local

519 s under load, which is not comparable to the earlier 274 s measurement;

Release query scenario passed its 45 ms gate, but

including duplicate generated

* Acceptance

The cutover is complete only when the Scheme suite, full Rust workspace test
matrix, strict policy, source-roundtrip/graph checks, consumer fixtures, and
current AOT performance gates pass at the exact PR head on required platforms.
An individual green fixture or a decreasing failure count is progress, not
completion.

The tracked =.snap= files are AST and consumer regression baselines, including
four direct Scheme-to-Rowan =GraphRecord= snapshots. Do not delete or approve
them merely to make migration tests green. A changed graph snapshot requires
review of kind, fields, ancestry, source ranges, and the source-roundtrip
assertion; generated =.snap.new= files remain unapproved candidates. Numeric
=syntax_kind= changes alone can be accepted only after confirming the semantic
graph is otherwise unchanged. The bare-AST snapshot was reviewed and updated
for Scheme-owned exact list bullets, a description body's separator-free text,
an unnamed source block's absent =NAME=, and coalesced contiguous plain text;
explicit assertions cover the first three. Passing local integration tests do
not establish complete Org-mode coverage or cross-platform release readiness.
