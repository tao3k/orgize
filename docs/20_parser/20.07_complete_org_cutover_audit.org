#+title: 20.07 Complete Org Parser Cutover Audit
#+startup: overview

* Verdict

The current Scheme-AOT/Rowan product is a lossless structural slice, not an
Org parser replacement.  The generated element inventory names 30 element
types and 24 object types, while =parser.ss= admits headlines/sections and
source blocks only.  The public =ParseConfig::parse= path still invokes the
handwritten Rust =document_node=.  Three-platform CI and source roundtrip
therefore establish neither complete syntax nor public API parity.

Run the read-only differential inventory with:

#+begin_src sh
cargo run --locked --example org_cutover_audit
#+end_src

The input is the Git-tracked
=tests/fixtures/org-elements/representative.org=.  Its public tree currently
contains 30 distinct node kinds (including affiliated keywords, links,
emphasis, lists, tables, planning, drawers, footnotes, and timestamps); the
generated tree contains five kinds.  Both reproduce the source.  This is the
counterexample to treating losslessness as syntax completeness.

* Blocking contracts

| Boundary | Current evidence | Required admission |
|----------+------------------+--------------------|
| Grammar authority | =grammar.ss= plus POO =parser.ss= declare line structure | Every element/object recognition rule and containment restriction is Scheme-owned; no downstream Rust parser rule or generated scanner program |
| Engine | Generic section and opaque-block executor | Bounded contextual Parser IR, recursive element/object strategies, typed recovery, source-backed events, and deterministic AOT validation |
| Syntax coverage | Headlines, sections, source blocks, text lines | All 30 elements and 24 objects, affiliated keywords, configuration-dependent syntax, malformed inputs, and object restrictions |
| Public AST | Generated Rowan uses a separate kind catalog | Generated typed nodes/fields and source spans preserve the =Org=, query, export, and document contracts |
| Cutover | =ParseConfig::parse= calls Rust =document_node= | Exactly one generated parse path; old handwritten lexer/element/object parser removed only after full differential parity |
| Evidence | Focused structural tests and source roundtrip | Exact AST fixtures, negative/recovery cases, pinned full corpus, independent public-consumer tests, and equivalent-semantics performance receipts |
| Org contract | The expression grammar now has a Scheme-owned AOT Rust/Rowan product, but Rust still owns contract policy, query compilation, evaluation, lint, CLI and workspace logic | One Org-owned Scheme/POO contract module owns syntax, policy, query and evaluation; Rust retains only typed AOT execution, filesystem/process handoff and public transport projection |

* First typed failures

1. The generated parser maps the representative document's list, table,
   drawer, planning line, link, emphasis, timestamp, and footnote to generic
   text lines.  Their inventory entries are metadata, not parsing rules.
2. The structural executor closes an unterminated source block at EOF.  The
   pinned =org-element.el= reference's incomplete block parsers instead return
   paragraph parsing.  Recovery policy must be declared and tested, not
   inferred from lossless source text.
3. =parse_structural_lines= currently returns a green node without the normal
   parse receipt or generated typed field projection.  It cannot be substituted
   into public =Org::parse= without a second AST authority.
4. There is no element/object-complete, Git-tracked differential corpus.  The
   =.data/org-mode= checkout is reference evidence outside the Git-scoped
   fixture boundary; it must not become a runtime or CI input.
5. =org-contract= is not yet a Scheme policy.  Moving only its constants or
   introducing a second Scheme model beside the Rust evaluator would increase
   authority count instead of reducing Rust responsibility.

* Completed expression-parser cutover within the larger MVP

=languages/org/v1/modules/org-contract/grammar.ss= now defines expression
syntax. Its reproducibly generated Rust table is consumed by the existing
public query and contract-expression entrypoints. The former independent
Rowan S-expression scanner and syntax-kind catalog in =core_parser.rs= are
gone; that file only lowers the generated CST to the existing query value.
The same grammar is checked by a Scheme AST fixture and Rust tests covering
comments, adjacent escaped strings, Unicode whitespace, malformed input,
source roundtrip, and the existing contract property-scope scenario. This is
an owner replacement, but *not* the vertical MVP: the Org document parser
still uses =document_node=, and contract policy/evaluation still live in Rust.

* Org contract module chain

The contract owner belongs under
=languages/org/v1/modules/org-contract/= with one public =interface.ss=. Follow
the POO Flow role direction =types -> objects -> funs -> config -> interface=:

- =types.ss=: closed contract, assertion, scope, severity, reference and query
  vocabularies, shape admission, and diagnostics.
- =objects.ss=: POO contract/assertion/query values and named constructors;
  extension is through prototypes or a one-receiver generic only where a
  behavior actually varies.
- =funs.ss=: pure contract parsing, reference resolution policy, query
  combination, assertion evaluation, and receipt construction. Use functional
  combinators for traversals and indexes; no IO or unbounded shell execution.
- =config.ss=: maintained Org contract profiles and explicit provider/runtime
  handoff selection. Use CLOS methods only for genuinely independent provider
  and contract-kind axes.
- =interface.ss=: the sole public import; it re-exports the four role owners
  and contains no second implementation.

The downstream Rust product must project this admitted POO module through the
same development-time AOT boundary as the parser. Cargo users do not install
Gerbil. Existing Rust model/evaluator code is deleted only when corresponding
public lint, trace, workspace, query, JSON and negative tests pass against the
generated product. A file rename or a second shadow evaluator is not a cutover.

Scheme owns declarations and pure semantic policy, not the downstream scanner
runtime. =gerbil-parser= may interpret a lexical rule in Scheme for its own
authoring tests, but the shipped Cargo path uses the same rule as a generated
Rust table entry and executes it in the shared Rust lexer. Org must not add a
second Scheme scan implementation, a generated Org-specific scan program, or
handwritten Rust lexer. Measure and optimize the shared Rust lexer only after
the syntax output is equivalent to the public parser.

* Implementation order

This is one vertical MVP followed by full-coverage expansion, not separate
deliverables called a scanner MVP, element-inventory MVP, and contract MVP.

The MVP workflow is the existing Git-tracked =contract_org_property_scope=
scenario: load =inputs/contracts.org= and =inputs/notes.org=, parse both,
project the element graph, evaluate the document/subtree =org-contract=
assertions, and return the same public trace and lint results. It exercises
headlines, sections, property drawers, node properties, links, source blocks,
query bindings, scopes, count/exists assertions, and real CLI consumers. The
generated parser and Scheme-owned POO contract module must both participate;
source roundtrip or a separate demo API does not satisfy this MVP.

Before calling that workflow done:

1. Replace the separate =parse_structural_lines= decision path with one
   existing v1 Grammar/Parser IR pipeline. The local contract-expression
   Rowan parser has already moved to a Scheme-owned generated grammar.
   =gerbil-parser= may add generic contextual strategy and lexical primitives;
   it must not gain Org rules. Scheme POO declarations in orgize supply the
   actual rules and contract behavior. This is an implementation dependency,
   not an independently releasable feature.
2. Generate immutable Rust products and typed CST accessors from the Scheme
   owners. The Cargo consumer needs no Gerbil installation. One grammar digest,
   source digest, and contract/module identity bind the parse/evaluation
   receipts; no handwritten scanner or fallback path is permitted.
3. Run exact AST, graph, query, contract trace, lint and negative-case parity
   against the existing public behavior for the fixture pair. Include a
   malformed contract, an unclosed block, UTF-8 spans, and source roundtrip.
4. Route the scenario's public consumers to the generated product and remove
   the displaced Rust parser/contract-expression owner code in the same change.
   A second dormant implementation or a new side API is not MVP closure.
5. Measure equivalent outputs with ASP Rust Dev Gate scenarios before accepting
   throughput, allocation, or peak-memory claims.

After the vertical MVP, expand the same Scheme/POO product and parity corpus
to all 30 elements and 24 objects, configuration variants, malformed input,
query/export/document consumers, and the complete =org-contract= lint, trace,
workspace and JSON surfaces. Only then switch the general =Org::parse= facade
and delete the remaining handwritten Rust syntax parser. The draft PR remains
open until that full cutover; green focused tests do not change its status.

Performance comparison is meaningful only between equivalent syntax and
query outputs.  Record throughput, allocation, and peak memory against the
current public parser on representative and pathological documents using the
ASP Rust Dev Gate after semantic parity; the 10,000-section smoke test is not
a substitute for those receipts.
