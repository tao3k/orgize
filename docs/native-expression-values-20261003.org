#+TITLE: Scheme-owned expression values and expectation grammar

* Authority and implementation

The public Org parser remains native Gerbil AOT. Both =runtime-rust= and
=runtime-scheme= use the same native request owner, exception containment and
call-scoped byte ownership. No Gambit modification or legacy parser was added.

Query, Contract and selector expression consumers now request Scheme-cooked
expression values directly, instead of building a Rowan CST and recursively
lowering it again in Rust. The canonical expression grammar still admits the
source once. Scheme owns quoted-string escapes, including the existing policy
for unknown escapes. Rust only checks the typed tape's identity, UTF-8, lengths,
tags and balanced list structure.

The private =ONR1= operations are Org events (0), expression CST (1),
expression values (2), and expectation values (3). =OXV1= value tapes carry
the producing grammar digest. The existing lossless =OEV1= CST path remains
available for native CST tests. It is not a fallback.

=modules/org-contract/expectation-grammar.ss= declares exactly one expectation:
=exists=, =not exists= or =count= with one of six comparisons and an unsigned
decimal count. Whitespace and hash comments are grammar extras, including CRLF.
Scheme rejects adjacent =notexists= words and counts beyond the native u64
range. Rust performs enum projection and checked host-size conversion, not
source-line splitting, comment stripping, operator scanning or string unescaping.

* Remaining full-migration gates

This slice removes the remaining Rust expression-string and expectation source
scanners. It does not establish complete Org semantic or performance closure.
The typed Query/Contract semantic compilers, form admission and metadata
interpreters still have Rust ownership and require an explicit follow-up audit.
Exact syntax-token diagnostics, full consumer/recovery conformance, lifecycle,
installed Python wheel verification and matched 1,000/10,000-document Tokio
comparisons remain separate gates. Old receipts cannot qualify this candidate.

Workspace dev opt-level 2/build-override 2 and release opt-level 3/Thin LTO
remain unchanged. Both scheduling choices and original concurrency stay enabled.
