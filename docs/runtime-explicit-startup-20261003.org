* Breaking admission contract
The host calls unsafe Rust initialize_native_runtime, Python
orgizepy.initialize_native_runtime, or shared C ABI revision 2
orgize_shared_runtime_initialize before application workers or children.
Imports, parsing and Contract evaluation never start the owner implicitly.
There is one process-lifetime owner. Repeated calls return the original startup
result; initialization failure is terminal, and restart/unload is unsupported.

The first call needs an exclusive host startup window: valid descriptors 0/1/2,
no live or newly spawned children, concurrent native initialization, stdio
users or signal-disposition changes. The linked Scheme parser may not use
Scheme-owned stdio, terminals or subprocesses. The boundary captures host
stdio flags and SIGINT/SIGTERM/SIGCHLD/SIGPIPE/SIGQUIT/SIGWINCH/SIGCONT
dispositions, starts the selected owner, and restores those resources before
publishing successful request admission. Restoration is attempted even if
native initialization reports failure. No restoration runs on ordinary parses.
The GIL does not establish process-wide startup exclusivity.

Native heartbeat/processor signals remain runtime-owned. Blocked host signal
mask policies, interruption during the startup window, shared external open
file descriptions, closed/rebound stdio, dynamic unloading and native-owned
terminal/subprocess behavior are not qualified. This is a POSIX parser-host
contract, not general Gambit signal isolation or an unrestricted embedding API.
