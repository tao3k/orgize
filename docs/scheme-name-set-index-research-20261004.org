* Algorithm and ownership
=line-bytes-in-set?= previously validated the entire sorted ASCII name table
and searched it linearly on every evaluation. The candidate derives a vector
index once on first use of each immutable IR table in a parse, then compares
source byte spans against that vector using binary search. It does not allocate
a substring or UTF-8 copy for comparison. ASCII admission establishes that
character order and byte order agree.

The identity-keyed derived-index cache is bounded at 128 tables and reset by
=run-event-fold= on every request. No global cache retains source or caller IR.
Tables may be changed by callers BETWEEN requests; each new request validates
them again. This is not a concurrent mutable-IR guarantee within one admitted
fold. State values, range validation and event ordering are not cached away.
The original public =fold-static-name-set= validator remains unchanged.

This trades repeated O(N) table admission/search for once-per-parse admission
and O(log N) search comparisons (each comparison still examines name bytes).
It does not accelerate unrelated fold predicates, state updates or other
full-parser work. An additional per-parse hash table is currently allocated even
if a document never evaluates a name-set predicate; lazy construction is a
separate unimplemented candidate, not a claimed improvement.
