#+title: Org v1 module capability map

* Scope

The Scheme modules in this directory own the Org language boundary.  Their
source is the Org document and its syntax, not an application category such as
"AI Memory".  =org-parser= recognizes source events, =org-elements= owns
Element/Object meaning and document-local queries, and =org-contract= records
the source contract used by generated projections.  The current directory has
those three modules; the capabilities below are an implementation map, not a
claim that every listed projection is already Scheme-complete.

The Org and Emacs package ecosystem is comparison evidence for what a user can
do with the same document.  We should preserve its useful composability without
copying Emacs UI buffers, package-specific configuration, or a second parser.
In particular, =org-super-agenda= groups entries after an ordinary Org agenda
command has selected them.  Grouping changes a view; it does not create new
source facts ([[https://github.com/alphapapa/org-super-agenda][upstream package]]).
"Org notes" here means the broader capture, refile, ID/link, attachment,
annotation, archive, and review ecosystem, not one package or a new Org type.

* Ownership by source capability

| Source capability | Scheme owner and evidence | Consumer composition |
|-------------------+---------------------------+----------------------|
| Planning, TODO, priority, tags, repeaters, habit | =org-parser= events and =org-elements= headline/planning/LOGBOOK facts with spans | Agenda selection, grouping, sort, and review views |
| Capture and refile history | Standard headings, properties, links, timestamps, and recorded LOGBOOK/refile events | Capture policy, edit execution, and task workflow |
| Notes and associations | =ID=/=CUSTOM_ID=, targets, links, attachments, outline context, source spans | Cross-document index, backlinks, annotation UI, retrieval |
| Review over time | Planning/repeater signal plus the distinct recorded action and outcome events | Explicit-time due policy, evidence reassessment, retention scheduling |
| Historical and current use | Archived/closed/current source facts, source cut, correction and links | Scoped decision policy and evidence admission |

The existing =org-elements/queries.org= declares bounded document-local
queries.  A super-agenda-like grouping plan should compose admitted query rows
and preserve each row's Org source anchor; it must not reparse text or silently
expand the selected set.  A note or review projection should likewise reuse
the same Element IDs, spans, and LOGBOOK facts.  A heading title is a search
hint, not identity, supersession, or proof.

On this source cut, the richer =AgendaViewPlan= / =AgendaBlockViewPlan= and
=AgentCapturePlan= implementations remain in =src/semantic_ast/=, outside this
Scheme module collection.  They are useful existing behavior and conformance
inputs, not evidence that the planned Scheme capability boundary is already
complete.

The current =memory-headline-state= is a Scheme-owned headline projection.
The broader Rust =AgentMemorySnapshot= authority/card logic has not yet been
migrated into these Scheme modules.  That work should be decomposed by the Org
capabilities above rather than moved into a standalone Memory authority
module.  Existing compact =MEMxxx= output is a consumer view over these facts.

"Short-term" and "long-term" describe a useful learning trajectory, but no
Org syntax token or storage tier promotes a note by itself.  A claim's current
validity needs source-bound evidence; a person's durable recall needs observed
retrieval or use.  These are different measurements.  Repeated presentation,
embedding similarity, a due date, and a heading's TODO state cannot substitute
for either measurement.

* From a fleeting thought to durable knowledge

1. Capture the thought as an ordinary Org heading or note with a timestamp,
   stable ID when needed, source context, and optional links.  =org-parser= and
   =org-elements= preserve that observation without calling it true or durable.
2. A Session asks an Org Element query for candidates within a stated source
   cut and scope.  The current named queries support bounded document-local
   Element predicates and lineage; they do not yet join notes across files,
   order a time series, or aggregate review outcomes.  A cross-document index
   must return source anchors for a caller to validate.
3. A review intent uses ordinary planning, repeater, habit, and LOGBOOK evidence
   to decide when to revisit.  The attempt records whether the idea was
   recalled, applied, contradicted, or left uncertain.  The Session owns that
   attempt and policy; Orgize owns the source events it reads.
4. Consolidation writes a new linked Org claim or procedure, retaining links
   to the fleeting observations, successful uses, and counterexamples.  Later
   review can revise or retract that claim.  Durable knowledge is thus an
   assessed, versioned result, not a rename of a note or a count of reads.

This is the intended analogue of a compact agent =MEMORY.md= summary.  If an
input is literally Markdown, it requires an explicit source-preserving import
or a Markdown-specific adapter before Org Element queries can address it;
Orgize does not parse Markdown as Org by assertion.

* Conformance gates

1. Pin upstream Org and selected package behavior as research fixtures.  For
   each behavior, record source syntax, exact input, expected selection or
   grouping, and any UI-only part that Orgize does not implement.
2. For planning and notes, exercise the same document through parser events,
   Element properties, named queries, and any compact projection.  Preserve
   source ID/span/cut throughout.  The source bytes to graph binding is a
   separate required receipt; a caller-supplied graph alone cannot attest it.
3. For review, show that an overdue repeater, a recorded action, a successful
   recall, and a current factual verdict remain distinct.  A later source cut
   keeps prior observations but requires a fresh current assessment.
4. Qualify Scheme behavior first and compare generated execution projections
   against it.  No package-inspired feature gets authority from merely matching
   a display row or a note title.
